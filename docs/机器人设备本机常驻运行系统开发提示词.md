# 机器人设备本机常驻运行系统开发提示词

版本：v1

用途：将“完整提示词”部分交给 AICode、Codex、Claude Code 或其他编码智能体，用于从零开发一个直接运行在机器人设备本机的常驻运行系统。

## 需求定位

需要开发的系统应准确命名为“机器人设备本机常驻运行系统（Robot Device Runtime）”。

它直接部署在机器人本机计算单元上，只管理这台机器人的运行。它不是上位服务器中的集群代理，也不是管理多台机器人的调度程序。它负责协调本机控制功能，并与上位调度服务通信：

- 设备功能调用和执行顺序；
- 控制器返回结果及异步进度；
- 首次注册、身份和密钥；
- HTTP 连接复用、断线检测和重连；
- 命令拉取、持久化、去重、执行和 ACK；
- 设备、任务、连接和安全状态切换；
- 心跳、遥测和状态变化上报；
- 进程崩溃、断网和设备重启后的恢复；
- 急停抢占、本地安全保持和人工介入；
- 日志、指标、诊断和服务运行管理。

## 完整提示词

你是一名负责机器人设备运行时、可靠通信和本机功能编排的高级软件工程师。请从零设计并实现一个“机器人设备本机常驻运行系统（Robot Device Runtime）”。

该系统直接运行在机器人设备本机，只负责本机机器人的状态和动作。它作为后台服务长期运行，调用本机控制功能、接收执行结果，并与上位调度服务保持可靠通信。它必须管理状态机、定时发送真实遥测、处理重复命令，并在断网、超时、进程崩溃和设备重启后恢复。

不要只输出概念方案或空项目。先形成需求、设计和任务文档，再按任务顺序完成可运行代码、测试、命令行管理工具和使用文档。所有功能必须真实实现，不得保留 `TODO`、空函数、假成功返回或未接线的界面。

## 一、开发前提

### 1. 本机运行边界

系统部署在机器人设备本机，只管理本机设备，不实现多机器人清单、跨设备任务分配、集群状态汇总或多租户能力。

`DEVICE_CODE` 是本机机器人向上位调度服务登记时使用的身份字段，不是本系统内部用于管理多个机器人实例的分区键。

### 2. 设备能力边界

机器人实际状态读取和动作执行必须通过 `runtime_adapter` 抽象完成。常驻运行系统不得把 HTTP 通信、任务状态和重试逻辑耦合到某个 ROS 话题、厂商 SDK 或 Gazebo 插件中。

本次先实现完整的适配接口、生命周期和错误处理。只有在目标设备协议已经明确时，才实现相应设备适配器。

不得在生产运行入口内生成随机位置、电量、状态、进度、任务结果或检测结果。无法读取的可选字段应省略。

### 3. 技术栈选择

优先服从目标仓库已有技术栈。如果是全新项目且没有强制技术要求，默认使用：

- Python 3.12；
- `asyncio` 结构化并发；
- `httpx.AsyncClient` HTTP 连接池；
- Pydantic 配置和协议模型；
- SQLite WAL 模式作为本地持久化；
- Alembic 或等价迁移机制；
- `pytest`、`pytest-asyncio`；
- 标准日志或结构化 JSON 日志。

禁止以多个无管理关系的后台线程和无限循环拼接系统。所有长期任务必须有明确所有者、取消机制、超时和退出顺序。

## 二、系统目标

系统必须达到以下目标：

1. 本机运行系统可以作为系统服务持续运行，不依赖交互式终端。
2. 设备控制器短暂不可用时，系统进入降级状态并持续诊断，不伪造在线状态。
3. 上位调度服务不可用时，机器人按本地安全策略运行，遥测和 ACK 可恢复发送。
4. 命令采用至少一次投递，但同一命令的物理动作不得被自动重复执行。
5. ACK 只表示命令处理结果，任务实际状态由任务遥测确认。
6. 急停和安全保持可以抢占普通命令，且不依赖普通任务队列畅通。
7. 状态、命令、任务和发送队列在重启后可恢复。
8. 所有关键行为可以通过日志、状态命令和诊断报告追踪。

## 三、核心组件

实现以下组件，并保持单一职责：

| 组件 | 职责 |
| --- | --- |
| `RuntimeSupervisor` | 本机系统生命周期、启动顺序、任务监督、故障传播和优雅退出 |
| `StateCoordinator` | 设备、连接、任务和安全状态的唯一写入者 |
| `RuntimeAdapter` | 读取真实状态、提交动作、查询动作结果和请求安全停止 |
| `RuntimeEventConsumer` | 接收控制器异步返回、状态变化、进度、故障和安全事件 |
| `GatewayClient` | 注册、遥测、命令、ACK、校正等 HTTP 调用 |
| `ConnectionManager` | HTTP 连接池、逻辑在线状态、认证失败和退避重连 |
| `CommandPoller` | 周期拉取命令，写入持久化 inbox |
| `CommandDispatcher` | 校验、排序、抢占、调用处理器和归一化结果 |
| `CommandRegistry` | 命令名称到具体处理器的显式映射 |
| `MissionManager` | 当前任务上下文、任务状态机和执行恢复 |
| `TelemetrySampler` | 按固定周期读取设备实际快照 |
| `TelemetryPublisher` | 按序发送持久化 outbox 中的遥测 |
| `AckPublisher` | 重试发送已确定终态的命令 ACK |
| `SafetyCoordinator` | 急停锁存、安全保持、释放检查和人工接管 |
| `LocalStore` | inbox、outbox、状态转换、任务上下文和迁移 |
| `HealthMonitor` | 控制器、上位服务、磁盘、时钟和工作协程健康检查 |
| `DiagnosticsService` | 生成脱敏状态快照和诊断报告 |

`StateCoordinator` 必须是状态的唯一写入入口。其他组件通过类型化事件请求状态变更，禁止多个协程直接修改共享状态。

## 四、RuntimeAdapter 接口

至少定义以下异步接口：

```text
initialize() -> AdapterCapabilities
self_check() -> SelfCheckResult
read_snapshot() -> RuntimeSnapshot
execute(command_id, command, payload, cancellation_token) -> InvocationResult
query_operation(command_id) -> InvocationStatus
reconcile_active_mission(execution_id) -> MissionReconcileResult
stream_events() -> AsyncIterator[RuntimeEvent]
request_safe_stop(reason) -> InvocationResult
is_safe_to_release() -> SafetyCheckResult
shutdown() -> None
```

接口要求：

- `execute` 必须接收上位命令 ID，并尽可能将该 ID 传递给控制器作为幂等标识。
- `query_operation` 用于崩溃恢复后判断物理动作是否已经执行。
- `stream_events` 用于持续接收控制器异步返回的状态、进度、故障和安全事件；如果设备只支持轮询，由适配器将轮询差异转换成相同事件模型。
- `read_snapshot` 不得等待网络请求。
- `request_safe_stop` 必须能绕过普通动作队列，直接进入高优先级安全路径。
- `shutdown` 必须有超时，超时后记录故障并结束进程。

统一返回模型 `InvocationResult` 至少包含：

```text
command_id
status: accepted | succeeded | rejected | failed | timeout | cancelled | preempted | outcome_unknown
error_code
message
started_at
finished_at
controller_operation_id
details
```

`RuntimeEvent` 至少包含 `event_type`、`observed_at`、`controller_operation_id`、`command_id`、`execution_id`、实际状态、进度、错误码和原始详情。系统必须先校验并持久化关键事件，再驱动状态机和上位遥测。

对于长时间运行任务，`execute` 可以返回 `accepted`，表示控制器已经接受动作；后续 `running`、进度和终态必须来自 `stream_events`、`query_operation` 或实际状态采样，不能由定时器自行推算。

如果控制器不支持按 `command_id` 去重或查询结果，在“动作已经触发但系统未能保存结果”的情况下，必须进入 `outcome_unknown`。此状态禁止自动重放物理动作，需要人工或控制器状态核对。

## 五、正交状态机

不要用一个巨大枚举混合所有状态。至少实现以下四套正交状态机。

### 1. 本机系统生命周期状态

```text
unprovisioned -> enrolling -> recovering -> running
                                  |           |
                                  v           v
                                blocked    degraded
                                  \           /
                                   -> shutting_down
```

最小状态：

- `unprovisioned`：缺少设备专属密钥；
- `enrolling`：正在首次注册；
- `recovering`：恢复本地状态和未完成动作；
- `running`：关键组件正常；
- `degraded`：仍可运行，但部分依赖不可用；
- `blocked`：需要人工处理，不能自动继续；
- `shutting_down`：停止接收新动作并保存状态。

### 2. 连接状态

```text
unknown -> online -> offline -> online
               |        |
               v        v
          auth_failed  disabled
```

最小状态：`unknown`、`online`、`offline`、`auth_failed`、`disabled`。

连接状态是逻辑状态。当前通信方式是 HTTP 命令轮询和请求发送，不得虚构设备 WebSocket、MQTT 或服务端推送通道。

### 3. 安全状态

```text
normal -> stopping -> safe_hold -> release_check -> normal
   |                        |
   +--------------------> fault_hold
```

最小状态：`normal`、`stopping`、`safe_hold`、`release_check`、`fault_hold`。

安全状态优先于设备状态和任务状态。`global_estop_active=true` 时必须立即请求本地安全停止，不等待对应 `estop` 命令出现。

上位急停解除不等于设备可以恢复。只有收到明确 `release` 命令且 `is_safe_to_release()` 成功后，才允许从安全保持退出。退出后仍不得自动恢复运动。

### 4. 任务状态

内部状态可以包括：

```text
none -> starting -> accepted -> running -> completed
                             -> pausing -> paused -> resuming -> running
                             -> cancelling -> cancelled
                             -> failed
```

上报给上位服务的状态只允许：

- `accepted`；
- `running`；
- `paused`；
- `completed`；
- `failed`；
- `cancelled`。

终态不可逆。ACK、命令已拉取、动作已提交都不能替代任务状态遥测。

## 六、命令处理生命周期

每条命令必须经历持久化生命周期：

```text
received
  -> validated
  -> dispatching
  -> accepted | failed | outcome_unknown
  -> ack_pending
  -> acked
```

命令处理顺序：

1. 从上位服务拉取命令。
2. 在执行前将完整命令、载荷哈希和接收时间写入 inbox。
3. 如果命令 ID 已存在，核对命令名称和载荷哈希。
4. 相同命令 ID、相同载荷时返回已保存结果，不重复执行。
5. 相同命令 ID、不同载荷时记录协议冲突并禁止执行。
6. 校验设备能力、当前任务、安全状态和前置条件。
7. 将状态写为 `dispatching` 后调用 `RuntimeAdapter`。
8. 原子保存执行结果和待发送 ACK。
9. ACK 成功后标记为 `acked`，但保留去重记录。
10. 任务命令继续通过任务遥测报告实际进度和终态。

### 命令优先级

动作调度至少使用以下优先级：

| 优先级 | 命令 |
| --- | --- |
| P0 | `estop`、本地安全故障 |
| P1 | `mission_cancel`、`mission_pause`、设备级 `pause` |
| P2 | `release`、`reset`、`reset_pose` |
| P3 | `mission_start`、`mission_resume`、设备级 `resume` |

P0 可以抢占任何普通动作。P1 是否能抢占当前动作由适配器能力决定，但必须尽快进入安全过渡。普通动作默认串行执行。

已有活动任务时收到新的 `mission_start`，不得启动第二次任务，应返回稳定错误码 `DEVICE_BUSY`。不同命令 ID 携带相同 `execution_id` 时，也不得重复启动任务。

### 支持命令

必须实现处理器注册和前置条件校验：

- `mission_start`；
- `mission_pause`；
- `mission_resume`；
- `mission_cancel`；
- `pause`；
- `resume`；
- `estop`；
- `release`；
- `reset`；
- `reset_pose`。

未知命令不得忽略或假成功，必须保存并以 `failed` ACK 返回稳定错误码 `UNSUPPORTED_COMMAND`。

## 七、并发与调度要求

本机系统至少运行以下独立工作任务：

| 工作任务 | 默认周期或触发方式 |
| --- | --- |
| 控制器状态采样 | 1 秒，可配置 |
| 控制器异步事件接收 | 持续运行 |
| 遥测 outbox 发送 | 新事件或重试时间到达 |
| 命令轮询 | 1 秒，可配置 |
| ACK outbox 发送 | 新 ACK 或重试时间到达 |
| 控制器健康检查 | 2 秒，可配置 |
| 本地状态检查点 | 状态变化触发，另加周期兜底 |
| 过期数据清理 | 低频定时任务 |
| 进程内部 watchdog | 1 秒，可配置 |

周期调度要求：

- 周期计算使用单调时钟；业务时间使用 UTC ISO 8601。
- 某次任务执行过慢时，不允许随后连续补发多个周期造成洪峰。
- 遥测采样不得等待遥测网络发送。
- 命令执行不得阻塞遥测、安全检查或 ACK 重试。
- 任务状态、安全状态和关键故障变化必须立即写入 outbox，不得只等待下一次周期遥测。
- 周期遥测用于心跳和最新快照，事件遥测用于不可丢失的状态转换，两者必须使用统一序号排序。
- 大型点云或地图上传必须使用独立限流队列，不能占满控制命令和心跳连接池。
- 内部队列必须有容量限制和背压策略，不能无限占用内存。

## 八、连接管理

使用长期复用的 HTTP 连接池，但不要把 TCP 连接是否存在当作设备在线的唯一判断。

连接管理必须：

1. 记录最近一次成功请求时间和连续失败次数。
2. 区分上位服务离线、设备控制器离线、认证失败和设备被禁用。
3. 对网络错误、HTTP 429 和 5xx 使用有上限的指数退避及少量抖动。
4. 对 401、403、409、422 不得无脑高频重试。
5. 请求超时后将结果标记为“未知”，按接口幂等规则处理。
6. 重连后优先处理安全状态、ACK 和关键任务转换，再处理普通遥测。
7. 提供连接池、超时、最大并发和退避参数配置。

重连时不能把大量旧普通状态瞬间发送并覆盖当前状态。允许压缩被新状态完全覆盖的普通设备快照，但不得丢弃任务状态转换、安全事件、故障、ACK 和校正结果。

## 九、本地持久化

使用事务型本地存储，默认 SQLite WAL。至少包含以下数据：

### 1. `runtime_meta`

- 数据库版本；
- 当前和历史 `boot_id`；
- 每个 `boot_id` 已分配的最后 `sequence`；
- 当前本机系统生命周期和检查点；
- 最近一次干净退出标记。

### 2. `command_inbox`

- `command_id` 主键；
- 命令名称；
- 原始载荷；
- 载荷哈希；
- 优先级；
- 接收时间；
- 执行状态；
- 控制器操作 ID；
- 最终结果；
- 重试和错误信息。

### 3. `telemetry_outbox`

- `event_id` 主键；
- `boot_id`；
- `sequence`；
- 事件类型；
- 请求体；
- 创建时间；
- 发送次数；
- 下次重试时间；
- 最后错误；
- 确认时间。

同一 `boot_id` 的遥测必须按 `sequence` 顺序发送。旧序号不能越过新序号，否则旧事件将持续得到 409。

### 4. `ack_outbox`

- `command_id` 主键；
- 固定终态；
- 固定消息和详情；
- 发送次数；
- 下次重试时间；
- 最后错误；
- 确认时间。

ACK 一旦生成，重试内容必须完全一致。

### 5. `mission_context`

- 当前 `execution_id`；
- 任务、工序和目标；
- 当前内部状态；
- 最后上报状态；
- 进度和完成量；
- 待完成控制意图；
- 最后更新时间。

### 6. `dead_letters`

保存无法自动恢复的协议冲突、非法事件和结果未知动作，供诊断和人工处理。

所有数据库结构必须有迁移。数据库损坏、磁盘满或迁移失败时，系统不得继续执行新物理动作，应进入 `blocked` 或 `fault_hold`。

## 十、启动与恢复流程

启动必须严格按以下顺序：

1. 加载并校验配置，拒绝占位密钥和非法地址。
2. 打开本地数据库，执行迁移和完整性检查。
3. 检查上次是否干净退出。
4. 恢复安全锁存、当前任务、命令 inbox、ACK 和遥测 outbox。
5. 初始化 `RuntimeAdapter` 并执行自检。
6. 若存在结果未知动作，调用 `query_operation` 或进入人工阻塞。
7. 若已有设备专属密钥，使用该密钥恢复日常通信。
8. 若没有设备专属密钥，进入首次注册流程。
9. 生成新的 `boot_id`，但保留旧启动周期尚未确认的 outbox。
10. 立即读取并上报一帧实际设备快照。
11. 启动命令、遥测、ACK、健康检查和 watchdog 工作任务。

首次注册可能出现“服务端已创建设备并生成专属密钥，但响应在客户端保存前丢失”。当前协议没有自动找回该专属密钥的接口。遇到这种情况不得循环使用共享密钥重复注册，应进入 `blocked` 并输出人工恢复指引。

## 十一、优雅停止

收到停止信号时：

1. 停止拉取和接受新普通命令。
2. 保持急停和本地安全监控有效。
3. 请求当前可取消任务安全停止，或保存不可中断状态。
4. 将最后状态、任务上下文和未发送结果持久化。
5. 在配置的截止时间内尝试发送关键 ACK 和状态转换。
6. 关闭适配器和 HTTP 连接池。
7. 写入干净退出标记。

截止时间内无法完成的发送记录保留在 outbox，下次启动继续发送。不能为了“退出干净”而伪造 ACK 或任务终态。

## 十二、上位服务接口契约

基础地址配置为 `UPSTREAM_BASE_URL`，并包含 `/api` 前缀。

### 1. 首次注册

```http
POST /devices/gateway/register
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

首次响应中的 `device_gateway_key` 只返回一次，必须原子写入安全存储。

同一设备编码再次提交注册资料时，必须使用设备专属密钥，不能继续使用共享 `DEVICE_GATEWAY_API_KEY`。

### 2. 遥测

```http
POST /devices/gateway/{device_code}/telemetry
X-Device-Gateway-Key: <device_gateway_key>
```

必需字段：

```json
{
  "event_id": "设备内唯一事件 ID",
  "boot_id": "本次启动周期 ID",
  "sequence": 42,
  "frame_id": "map",
  "schema_version": "v1",
  "observed_at": "2026-07-22T01:00:05Z"
}
```

可以附带实际 `status`、`battery`、`position`、`section_id`、`health`、`metrics` 和 `mission`。

相同 `event_id` 可幂等重传。同一 `boot_id` 内 `sequence` 必须严格递增。

### 3. 命令拉取

```http
GET /devices/gateway/{device_code}/commands
X-Device-Gateway-Key: <device_gateway_key>
```

响应包含：

```json
{
  "device_code": "AGV-101",
  "global_estop_active": false,
  "commands": [
    {
      "id": "命令 UUID",
      "command": "mission_start",
      "payload": {},
      "created_at": "2026-07-22T01:00:00Z",
      "idempotency_key": "上位幂等键",
      "priority": 50
    }
  ]
}
```

命令在 ACK 前可能每次轮询都被重复返回。

### 4. 命令 ACK

```http
POST /devices/gateway/{device_code}/commands/{command_id}/ack
X-Device-Gateway-Key: <device_gateway_key>
```

```json
{
  "status": "acknowledged",
  "message": "controller processed command"
}
```

状态只能是 `acknowledged` 或 `failed`。相同终态和相同内容可安全重试；不同终态会返回 409。

### 5. 任务状态

任务状态通过遥测中的 `mission` 对象上报：

```json
{
  "mission": {
    "execution_id": "任务启动命令中的执行 ID",
    "state": "running",
    "progress": 32.5,
    "completed_qty": 18.0,
    "estimated_completion_at": "2026-07-22T02:00:00Z",
    "result": {},
    "failure_code": null
  }
}
```

### 6. 校正结果

```http
POST /devices/gateway/{device_code}/calibration
X-Device-Gateway-Key: <device_gateway_key>
```

校正事件必须有唯一 `event_id`，并报告实际来源、观测时间、成功状态、位置和漂移量。

接口字段和约束若与上位服务最新 OpenAPI 不一致，以 OpenAPI 为准，但不得静默忽略协议差异。应通过契约测试及时发现并报告。

## 十四、安全要求

1. 本地硬件急停优先于任何软件和网络命令。
2. 安全停止不得依赖上位服务在线。
3. `estop` 必须抢占普通执行。
4. `release` 只解除安全保持，不得自动恢复任务或运动。
5. 断网、定位失效、控制器失联、磁盘写入失败时使用明确的本地安全策略。
6. 设备密钥不得出现在日志、异常字符串或 CLI 参数中。
7. TLS 启用时必须验证服务端证书，不允许生产环境全局关闭验证。
8. 输入命令、坐标、进度、时间和扩展载荷必须有边界校验。
9. 诊断导出必须脱敏。

测试适配器可以使用确定性夹具，但生产入口不得引用测试适配器或自动演示数据。

至少实现以下测试层：

- 命令载荷哈希和冲突检测；

- ACK 内容冻结；

### 持久化测试

- WAL 重启恢复；
- 迁移升级；
- 命令执行前强杀进程；
- 命令提交后、结果保存前强杀进程；

- 遥测保存后、确认前强杀进程；

### 协议契约测试

- 首次注册和设备专属密钥保存；

- ACK 超时后以完全相同内容重试；
- mission 状态只由实际适配器结果驱动。

### 并发和安全测试

- `estop` 与 `mission_start` 同时到达；
- `estop` 与 `mission_resume` 同时到达；
- 安全保持期间收到 `release`；
- 控制器离线但上位服务在线；

- 控制器事件流中断后能够重建订阅或退化为状态查询；

- 连续运行至少 72 小时；

- 长时间断网后 outbox 有界且可恢复；

## 十九、EARS 验收需求

使用以下需求作为实现和测试的追踪基线：

- `R-001` WHEN 本机运行系统启动 THEN 系统 SHALL 在执行任何物理动作前完成配置、本地存储和安全状态恢复。
- `R-002` WHEN 设备尚未注册 THEN 系统 SHALL 使用 `DEVICE_GATEWAY_API_KEY` 完成一次注册并原子保存设备专属密钥。
- `R-003` WHEN 注册结果无法确认且专属密钥未保存 THEN 系统 SHALL 进入 `blocked`，不得循环注册。
- `R-004` WHEN 到达遥测周期 THEN 系统 SHALL 读取实际设备快照并先写入 outbox，再异步发送。
- `R-005` WHEN 遥测请求超时 THEN 系统 SHALL 使用原 `event_id` 重试。
- `R-006` WHEN 同一 `boot_id` 产生遥测 THEN 系统 SHALL 按严格递增 sequence 顺序发送。
- `R-007` WHEN 收到新命令 THEN 系统 SHALL 在调用设备前持久化命令和载荷哈希。
- `R-008` WHEN 重复收到相同命令 ID 和相同载荷 THEN 系统 SHALL 返回已保存结果，不重复物理动作。
- `R-009` WHEN 相同命令 ID 携带不同载荷 THEN 系统 SHALL 拒绝执行并记录协议冲突。
- `R-010` WHEN 命令执行结果确定 THEN 系统 SHALL 原子保存结果和固定 ACK 内容。
- `R-011` WHEN ACK 发送失败 THEN 系统 SHALL 以完全相同内容重试。
- `R-012` WHEN 控制器返回任务实际状态或进度事件 THEN 系统 SHALL 持久化该事件并立即通过 mission 遥测上报，不以 ACK 或定时推算替代。
- `R-013` WHEN 动作结果在崩溃后无法确认 THEN 系统 SHALL 进入 `outcome_unknown`，不得自动重放。
- `R-014` WHEN `global_estop_active=true` THEN 系统 SHALL 立即请求本地安全停止，不等待普通命令执行完成。
- `R-015` WHEN 收到 `release` THEN 系统 SHALL 先验证本地安全条件，且不得自动恢复运动。
- `R-016` WHEN 上位服务离线 THEN 系统 SHALL 维持本地安全并有界保存关键待发数据。
- `R-017` WHEN 控制器离线 THEN 系统 SHALL 停止提交新动作并报告独立的控制器故障。
- `R-018` WHEN 本地持久化不可写 THEN 系统 SHALL 停止接受新物理动作并进入安全故障状态。
- `R-019` WHEN 收到停止信号 THEN 系统 SHALL 按优雅停止顺序保存状态并在截止时间内退出。
- `R-020` WHEN 查询本机运行状态 THEN 系统 SHALL 分别返回进程、控制器、上位连接、任务、安全和队列状态。
