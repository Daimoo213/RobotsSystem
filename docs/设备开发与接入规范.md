# 设备开发与接入规范

版本：v1

## 1. 目的与边界

本规范定义真机或外部 Gazebo 桥接程序与机器人智能集群调度系统之间的接口。设备侧可以使用 ROS、ROS2、MQTT、厂商 SDK、Gazebo 插件或其他技术实现，但这些实现不放入本仓库。

系统后端只接受 HTTPS/HTTP JSON 网关请求，并通过持久化命令队列将调度、暂停、恢复、取消和安全命令交给设备桥接程序执行。

设备侧必须承担：

- 硬件急停和本体安全回路；
- 机端避障、速度限制和断网安全策略；
- ROS/Gazebo/厂商协议与本规范 JSON 的转换；
- 命令去重、持久化和实际执行；
- 状态、位姿、任务和传感器数据的真实上报。

平台不替代上述机端能力。

## 2. 设备开发功能需求

### 2.1 最小可接入能力

每台设备或仿真实体必须具备以下能力：

1. 使用唯一设备编码完成首次注册。
2. 安全保存本设备独立网关密钥。
3. 以固定周期上报真实心跳、状态、电量和 `map` 坐标。
4. 接收并去重执行后台命令，重复 ACK。
5. 接收任务启动、暂停、恢复、取消命令。
6. 对每次任务上报唯一执行 ID、实际状态、进度和完成量。
7. 在机端检测硬件急停、障碍、不可达、定位失效等情况，并报告真实失败或安全状态。

### 2.2 推荐扩展能力

- 功率、累计能耗、累计里程、累计运行时长、负载比例。
- 定位漂移、二维码/AprilTag 自动校正与人工校正结果。
- 激光 SLAM 生成的完整点云地图、mesh/OctoMap 外部资产。
- 摄像头注册和真实 AI 检测结果。
- 设备健康度、故障码、控制器软件版本和地图版本。

## 3. 通信总则

| 项目 | 要求 |
| --- | --- |
| 基础地址 | `http(s)://<平台地址>/api` |
| 编码 | UTF-8 JSON |
| 内容类型 | `Content-Type: application/json` |
| 坐标系 | 使用当前项目的 `map_frame`（默认 `map`）；单位为米；方向见 3.1 节 |
| 时间 | ISO 8601 带时区，例如 `2026-07-21T10:30:00Z` |
| 网关协议版本 | 当前为 `v1` |
| 命令投递 | 至少一次，设备必须按命令 ID 去重 |
| 设备身份 | 每台设备独立密钥，不可共享 |
| 操作员身份 | PM/O&M 使用 JWT；设备不得使用操作员 JWT |

### 3.1 `map` 坐标系方向约定

平台、机器人、完整点云、地图点位、区域、三维栅格和外部地图资产必须使用同一个项目地图坐标系。项目初始化字段 `map_frame` 只定义坐标系名称，默认值为 `map`；其几何约定如下：

| 项目 | 约定 |
| --- | --- |
| 类型 | 固定的右手笛卡尔坐标系 |
| 单位 | X、Y、Z 均为米 |
| 原点 | 现场联调时选定并记录的固定地图基准点；完整地图更新不得暗中改变原点 |
| `+X` | 从原点沿项目选定的现场基准方向 |
| `+Y` | 从 `+Z` 方向俯视地图时，由 `+X` 逆时针旋转 90° 的方向 |
| `+Z` | 竖直向上；`Z=0` 对应项目约定的高程基准面 |

俯视关系如下，观察者位于 `+Z` 一侧并看向原点：

```text
             +Y
              ^
              |
              |
原点 (0,0,0)  +------------> +X

+Z 垂直地图平面向上，指向观察者。
```

项目若与地理 ENU 坐标对齐，推荐使用 `+X=东`、`+Y=北`、`+Z=上`。未做地理配准时，不得自行假设 X 为东或 Y 为北；必须以现场交付的原点和基准方向记录为准。

设备或桥接器必须在上传前把 `odom`、`base_link`、传感器坐标系或厂商坐标转换到当前项目 `map_frame`：

```text
p_map = R_map_source * p_source + t_map_source
```

其中 `R_map_source` 是来源坐标系到项目地图坐标系的固定或实时旋转，`t_map_source` 是平移。只把 `frame_id` 字符串改成 `map` 而不转换数值属于无效数据。平台不提供 TF 查询或坐标变换服务；坐标转换、时间同步和外参标定由机器人、SLAM 节点或桥接器完成。

接口规则：

- `frame_id` 必须与当前项目 `map_frame` 完全一致，否则返回 HTTP 422。
- 设备位置和校准位置使用 `{x,y,z}`；完整点云的每个点使用 `[x,y,z]`；区域多边形使用水平面的 `[x,y]`，高度由 `min_z`、`max_z` 表示。
- 栅格配置的 `origin_x`、`origin_y`、`origin_z` 是栅格显示范围的最小角，不是新的地图原点，也不会改变设备或点云坐标。
- 当前 v1 标准接口只接收位置，不接收 `yaw`、欧拉角或四元数。设备不得依赖未定义的朝向字段执行平台任务。
- O&M 前端内部将地图坐标转换为 Three.js 的 Y 向上坐标：`(x_three,y_three,z_three)=(x_map,z_map,-y_map)`。接口调用方始终上传地图坐标，不得提前做该渲染转换。
- `mesh_gltf` 资产如需与点云直接重合，导出时应使用 `X_gltf=X_map`、`Y_gltf=Z_map`、`Z_gltf=-Y_map`；资产 `metadata.origin=[x,y,z]` 仍填写项目地图坐标。

示例：若现场把原点向右定义为 `+X`、向前定义为 `+Y`，则 `position={"x":12.0,"y":5.0,"z":1.2}` 表示设备位于原点沿 `+X` 12 米、沿 `+Y` 5 米并高于基准面 1.2 米。

建议设备遥测周期为 1 至 5 秒。平台默认心跳 TTL 为 5 秒，超过 15 秒未刷新会被视为离线候选。现场可根据网络条件调整后端配置，但设备不应依赖超长心跳间隔。

## 4. 凭据与注册

### 4.1 首次注册

```http
POST /api/devices/gateway/register
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

请求体：

```json
{
  "code": "AGV-101",
  "name": "Material AGV 101",
  "type": "agv",
  "model": "VENDOR-AGV-3",
  "protocol_version": "v1",
  "capabilities": {
    "processes": ["material_transport"],
    "max_speed_mps": 1.2
  },
  "section_tags": {"section": "A"},
  "permissions": {"travel": true, "work": true},
  "section_id": "A",
  "health": {"connection": "ok"}
}
```

响应会在首次创建时返回 `device_gateway_key`。该值只返回一次，必须写入设备、桥接服务或安全密钥管理系统。后续所有设备接口均使用此值。

### 4.2 已注册设备更新

再次提交同一设备编码时，请求头必须使用该设备的 `device_gateway_key`。共享引导密钥只允许新增设备，不能覆盖已注册设备的型号、能力、区域或权限。

### 4.3 能力声明要求

`capabilities.processes` 必须列出设备可执行的工序 ID。建议至少声明：

- `material_transport`：运输 AGV；
- `pit_excavation`、`site_prep`：挖掘设备；
- `precast_hoisting`、`vertical_transport`：吊装设备；
- `masonry_wall`、`tile_paving`、`plastering`：砌筑/装修设备；
- `safety_inspect`、`surveying`、`quality_check`：巡检设备。

设备类型、工序能力、电量和在线状态共同决定调度候选资格。设备不应声明无法稳定执行的工序。

### 4.4 单位产能声明

需要参与自动集群资源规划的设备，注册或更新时还必须在 `work_capacities` 中提供可审计的真实单位产能。只有同时满足工序能力、单位一致、产能有效、在线、空闲和电量阈值的设备才会被计入任务交付量覆盖；未提供产能的设备可以接入和上报，但不会被系统猜测为可完成某个工作量。

```json
{
  "work_capacities": [
    {
      "capability_code": "material_transport",
      "output_unit": "t",
      "rate_per_hour": 18.5,
      "source": "field_calibrated",
      "evidence_ref": "CAL-AGV-101-20260731",
      "reported_at": "2026-07-31T16:00:00+08:00",
      "measured_at": "2026-07-31T15:30:00+08:00",
      "valid_until": "2026-10-31T23:59:59+08:00"
    }
  ]
}
```

字段要求如下：

| 字段 | 要求 |
| --- | --- |
| `capability_code` | 必须与 `capabilities.processes` 中实际支持的工序或能力一致；辅助运输、吊装等角色可与任务主工序不同。 |
| `output_unit` | 必须与对应任务资源需求的工作量单位完全一致，不自动换算。 |
| `rate_per_hour` | 当前现场条件下经核验的每小时产出，必须大于 0；不得填写演示值或由平台默认补全。 |
| `source` | 仅接受 `manufacturer_rated`、`field_calibrated`、`telemetry_observed`、`contract_verified`。 |
| `evidence_ref` | 厂家资料、现场标定报告、遥测统计批次或合同核验记录的可追溯编号。 |
| `reported_at` | 网关确认该声明的时间，使用带时区 ISO 8601。 |
| `valid_until` | 可选；到期后自动不再参加新的资源规划。 |

同一设备、能力编码和单位的声明会被更新为最新的真实记录。设备侧应在型号、属具、作业条件或标定结果变化后重新提交，不能继续沿用失效产能。

## 5. 遥测接入点

```http
POST /api/devices/gateway/{device_code}/telemetry
X-Device-Gateway-Key: <device_gateway_key>
```

### 5.1 必填字段

| 字段 | 说明 |
| --- | --- |
| `event_id` | 本设备唯一事件 ID；相同 ID 重传应得到幂等成功 |
| `boot_id` | 控制器启动周期 ID；每次重启必须变更 |
| `sequence` | 同一 `boot_id` 内严格递增的整数 |
| `frame_id` | 当前项目坐标系名称，默认 `map`；方向必须符合 3.1 节 |

### 5.2 常用字段

```json
{
  "event_id": "7a1a1e16-9b91-4fc3-9c55-df6caeaf0001",
  "boot_id": "controller-20260721-01",
  "sequence": 42,
  "frame_id": "map",
  "schema_version": "v1",
  "observed_at": "2026-07-21T10:30:00Z",
  "status": "moving",
  "battery": 76.5,
  "position": {"x": 83.2, "y": 132.8, "z": 0.0},
  "section_id": "A",
  "health": {
    "location": "ok",
    "battery": "ok",
    "task": "ok",
    "safety": "ok"
  },
  "metrics": {
    "power_kw": 4.2,
    "energy_kwh_total": 18.7,
    "mileage_km_total": 4.8,
    "runtime_hours_total": 12.3,
    "payload_ratio": 0.55,
    "localization_drift_meters": 0.08
  }
}
```

规则：

- `observed_at` 不能超过服务端当前时间允许的未来偏差。
- 相同 `event_id` 允许重发，不应产生重复设备事件。
- 同一 `boot_id` 的 `sequence` 小于或等于已接受序列时，服务端返回 409；设备应丢弃或重新整理乱序缓存。
- `battery` 范围为 0 到 100；位置单位为米。
- `frame_id` 与项目 `map_frame` 不一致时返回 422；设备必须先完成坐标转换再重试。
- 未提供的指标不会由后端估算。

## 6. 任务执行接入点

任务执行信息通过遥测中的 `mission` 对象上报：

```json
{
  "mission": {
    "execution_id": "平台下发 mission_start 时的 execution_id",
    "state": "running",
    "progress": 32.5,
    "completed_qty": 18.0,
    "estimated_completion_at": "2026-07-21T11:20:00Z"
  }
}
```

可用状态：`accepted`、`running`、`paused`、`completed`、`failed`、`cancelled`。

状态顺序：

```text
dispatched -> accepted -> running -> completed
                         -> paused -> running
                         -> failed
                         -> cancelled
```

失败时应同时上报 `failure_code` 与可审计的 `result` 内容，例如导航不可达、硬件故障、人工接管、围栏阻止或安全停机。

设备不得把“收到命令”当作任务状态变化。只有动作实际完成后才允许上报对应状态。

## 7. 命令接入点

### 7.0 投递方式与持续运行要求

当前机器人接收任务使用 **HTTPS 主动轮询**，不是服务端到机器人建立 WebSocket、MQTT 或反向 TCP 长连接。平台将命令先持久化到数据库；设备桥接程序在本地持续调用拉取接口。因此，即使设备短时断网、服务端重启或 ACK 请求超时，未终结命令仍会在后续轮询中再次出现。

设备桥接程序启动成功后，必须并行保持两条独立循环：

```text
遥测循环：采集真实状态 -> 持久化待发事件 -> POST telemetry -> 成功后确认本地事件
命令循环：GET commands -> 按 command_id 去重和持久化 -> 调用本机控制器 -> 持久化结果 -> POST ACK
```

建议正常运行时每 1 秒轮询一次命令；网络异常时采用有上限的指数退避。设备执行任务期间也不得停止轮询，否则无法及时收到 `mission_pause`、`mission_cancel`、`estop` 等控制命令。设备心跳仍应遵守 3.1 节后的 1 至 5 秒建议周期，命令轮询不能代替真实遥测。

命令为至少一次投递：在设备提交最终 ACK 前，同一命令可能重复返回。设备必须以 `command.id` 为去重主键，不能把 HTTP 请求次数当作新的控制意图。

### 7.1 拉取命令

```http
GET /api/devices/gateway/{device_code}/commands
X-Device-Gateway-Key: <device_gateway_key>
```

响应按优先级和创建时间返回未终结命令。设备必须持久化已处理的命令 `id`，因为网络超时后平台会重新投递。

响应中的 `global_estop_active=true` 表示全局急停处于保持状态。设备必须立即维持本地安全停止，并继续处理命令列表中的高优先级 `estop`；不得因轮询结果中同时包含其他命令而恢复运动。

### 7.2 设备端处理闭环

对每条拉取到的命令，设备接入程序必须按以下顺序处理：

1. 在本地事务中查询 `command.id`。若已有终态处理记录，绝不再次执行动作；若之前的 ACK 未成功送达，使用已保存的相同结果重发 ACK。
2. 对新命令先校验设备状态、本地安全条件、任务 `execution_id`、坐标系和本机可执行性；然后在本地持久化“准备处理”记录，再调用 ROS、厂商 SDK、控制器或 Gazebo 适配器。平台不提供这些本机执行实现。
3. `mission_start` 成功接收时，保存命令中的 `execution_id`、`workflow`、`allocation` 和必要作业上下文；先以遥测报告 `mission.state=accepted`，实际开始移动或作业后再报告 `running`。设备只执行本命令中 `allocation.assigned_qty` 的配额，不能把整项业务任务总量作为本机完成量。
4. 对暂停、恢复、取消、急停和相机开关，必须在本机安全动作已被控制器接受后才记录成功 ACK；实际暂停、恢复、取消和相机状态仍必须由后续遥测如实确认。
5. 将 ACK 结果持久化后调用确认接口。收到 2xx 才标记本地 ACK 已送达；网络失败时保持原记录并在后续循环重发。不得为重试生成新的命令 ID、任务执行 ID 或虚构状态。

`mission_start` 的 `failed` ACK 仅表示设备明确拒绝接收本次启动，例如本机故障、地图未验证、无法满足安全前置条件或执行实例冲突。此时还应以遥测报告可审计的实际设备状态；已开始执行后发生的失败，应通过遥测 `mission.state=failed`、`failure_code` 和 `result` 上报。

### 7.3 ACK 命令

```http
POST /api/devices/gateway/{device_code}/commands/{command_id}/ack
X-Device-Gateway-Key: <device_gateway_key>
```

```json
{"status": "acknowledged", "message": "controller accepted command"}
```

ACK 状态只能是 `acknowledged` 或 `failed`。重复相同终态 ACK 是安全的；同一命令不同终态会被拒绝。

ACK 只确认该控制命令已被设备接收、拒绝或完成相应本机处理，**不等于任务完成**。任务、阶段、工作量和返航结果以 `POST /telemetry` 中同一 `execution_id` 的 `mission` 数据为准。

### 7.4 命令语义

| 命令 | 设备侧要求 |
| --- | --- |
| `mission_start` | 保存 `execution_id`，按 `target` 和 `constraints` 启动任务；随后上报 `accepted`/`running` |
| `mission_pause` | 暂停当前指定任务；仅实际停止后上报 `paused` |
| `mission_resume` | 恢复指定暂停任务；仅实际恢复后上报 `running` |
| `mission_cancel` | 安全取消指定任务；仅清理或停止完成后上报 `cancelled` |
| `pause` / `resume` | 设备级控制；有任务时仍需通过任务遥测体现实际状态 |
| `estop` | 立即调用机端安全停止；同时保持硬件急停优先级 |
| `release` | 仅在设备本体安全确认后解除急停/保持 |
| `reset` | 按厂商约束重置控制器；不得绕过安全联锁 |
| `reset_pose` | 以指定 `map` 坐标系执行人工定位重置，随后上报校正结果 |

## 8. 操作员控制与设备回执

| 操作员动作 | 后端动作 | 设备必须完成的回执 |
| --- | --- | --- |
| 暂停任务 | 排入 `mission_pause` | 遥测 `mission.state=paused` |
| 恢复任务 | 排入 `mission_resume` | 遥测 `mission.state=running` |
| 改派运行中任务 | 先排入旧设备 `mission_cancel` | 旧设备遥测 `cancelled`，平台才向新设备下发启动 |
| 全局急停 | 向所有注册设备排入 `estop` | 每台设备 ACK，并保持机端安全状态 |
| 急停恢复 | 向所有注册设备排入 `release` | 设备确认物理安全后 ACK 和正常遥测 |

## 9. 地图、点云、校正和视觉接入点

### 9.1 完整点云地图

```http
POST /api/pointcloud/gateway/map
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

O&M 必须先在运维端打开“建图模式”，否则接口返回 409 且不会写入数据库。请求必填：`map_id`、`source_id`、`frame_id`、`observed_at`、`points`。每个点固定为 `[x,y,z]` 并遵守 3.1 节的右手 Z 向上约定；点云必须来自真实传感器或外部仿真桥接，并在建图端完成坐标转换、融合和抽样。平台不设置快照合并流程，也不在后端或前端再次抽样。相同 `map_id` 重试幂等，新的 `map_id` 替换当前完整地图。

操作员读取接口为 `GET /api/pointcloud/map`，状态接口为 `GET /api/pointcloud/status`，两者使用操作员 JWT。机器人不得使用这两个接口的操作员凭据；设备专属读取流程见 9.3 节。上传成功后，实时通道 `pointcloud` 发布完整地图数据。

### 9.2 地图资产

```http
POST /api/map/gateway/assets
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

支持 `mesh_gltf`、`octomap`、`geojson`。资产记录应包含 `event_id`、`source_id`、`asset_uri`、`frame_id`、观测时间和可选 SHA-256 校验和。

O&M 网页渲染 mesh 时，只接受与项目 `map_frame` 一致的坐标系及浏览器可访问的 HTTPS `.gltf`/`.glb` URL。glTF 轴转换遵守 3.1 节；对象存储必须配置 CORS，私有资产推荐使用短期签名 URL。

### 9.3 机器人地图同步

机器人使用首次注册获得的本设备独立密钥获取地图，不使用共享 `DEVICE_GATEWAY_API_KEY`，也不使用 PM/O&M 的 JWT：

```http
GET /api/devices/gateway/{device_code}/map-sync
X-Device-Gateway-Key: <device_gateway_key>
If-None-Match: "<last_etag>"
```

清单返回项目 `frame_id`、坐标约定、整图 `sync_revision`、真实区域、点位、外部资产引用和当前点云摘要。点云大数组不放入清单或任务命令；`pointcloud.has_data=true` 时再调用清单给出的 `download_path`。

设备侧必须按以下流程处理：

1. 启动后先加载上一份已验证地图及其 `sync_revision`，再向平台查询清单。
2. 304 表示地图未变化；200 且修订号变化时，将新清单和点云下载到临时位置。
3. 校验项目编码、`frame_id`、`map_id`、点数、每个 `[x,y,z]` 结构以及实际使用资产的 SHA-256。不得把下载成功等同于地图可用。
4. 使用旧 ETag 再查询一次清单；只有返回 304 时才允许原子切换到新地图。若返回新清单，说明下载期间地图已变化，必须丢弃临时结果并重新同步。
5. 校验失败、点云缺失、资产不可访问或版本变化时，继续保留上一份已验证地图，并按本体安全策略停车、限制任务或请求人工处理。不得部分覆盖正在使用的地图。

正常运行时应以低频周期和 ETag 查询清单，不得按遥测或心跳频率重复下载完整点云；网络或服务异常时采用指数退避。

完整字段、响应头和错误结构以 [DEVICE_GATEWAY_API.md](DEVICE_GATEWAY_API.md#机器人获取地图同步清单) 为唯一线协议定义。

### 9.4 定位校正

```http
POST /api/devices/gateway/{device_code}/calibration
X-Device-Gateway-Key: <device_gateway_key>
```

报告 `event_id`、自动或人工来源、观测时间、成功状态、二维码 ID、位置、漂移量和说明。此接口记录真实校正结果，不实现 ROS EKF 或视觉识别算法。

### 9.5 摄像头/视觉检测

摄像头有两条彼此独立的数据链路，平台不接收或转发视频字节流：

| 链路 | 用途 | 传输方式 | 平台保存内容 |
| --- | --- | --- | --- |
| 机器人机载摄像头视频 | O&M 人员实时查看机器人视野 | 摄像头或本地媒体网关向浏览器直接提供 HLS 或 MP4；平台只下发开关命令并保存地址和状态 | `enabled`、`is_online`、`stream_url`、`stream_protocol` |
| 摄像头/视觉网关检测 | 展示现场的真实识别统计 | 视觉网关完成本地采集和识别后，以 HTTPS JSON 上报一条结构化检测结果 | 检测时间、设备/车辆/人员数量、扬尘、边坡风险、合规率 |

#### 9.5.1 机器人机载摄像头

设备注册时应在 `capabilities.camera` 声明可控摄像头；运行中通过遥测的 `camera` 对象报告真实状态。视频地址必须是 O&M 浏览器可以直接访问的 HLS 清单或 MP4 URL，`stream_protocol` 只能为 `hls` 或 `mp4`。RTSP、厂商私有协议和 MJPEG 地址不能直接填入机载摄像头遥测；需要先在设备侧或现场媒体网关转换为 HLS/MP4。

视频链路为：`摄像头 -> 设备侧媒体服务/现场媒体网关 -> HLS 或 MP4 -> O&M 浏览器`。平台 API 中不上传帧、录像文件或视频二进制；`stream_url` 只是受控播放地址。媒体服务必须按实际部署配置浏览器可访问的网络路由、HTTPS/CORS 和观看鉴权，且不得把用户名、密码或设备网关密钥写入 URL。

O&M 发出开启或关闭操作时，平台会排入 `camera_enable` 或 `camera_disable` 命令。设备在本机完成传感器开关后 ACK，并在下一次遥测中上报：

```json
{
  "camera": {
    "enabled": true,
    "is_online": true,
    "stream_url": "<现场媒体网关提供的实际 HLS 地址>",
    "stream_protocol": "hls"
  }
}
```

只有 `enabled=true`、`is_online=true` 且存在匹配协议的播放地址时，O&M 才会尝试打开播放器。摄像头离线、转码服务异常或没有地址时，设备必须如实上报，不得沿用失效地址伪装为可观看。

#### 9.5.2 独立摄像头与视觉检测网关

```http
POST /api/cameras/gateway/register
POST /api/cameras/gateway/{camera_code}/detections
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

独立摄像头/视觉网关使用系统级 `DEVICE_GATEWAY_API_KEY`，而不是某台机器人的专属密钥。先登记摄像头编码、名称、安装位置、实际视频地址及地图平面位置；再在每次真实识别或真实统计完成后上报：

```json
{
  "detected_at": "<带时区的真实检测完成时间>",
  "excavator_count": 0,
  "truck_count": 0,
  "person_count": 0,
  "dust_level": "<视觉系统实际判定等级>",
  "slope_risk": "<视觉系统实际判定等级>",
  "ai_compliance_rate": 0
}
```

数值 `0` 只在画面实际检测为零时使用，不能作为占位数据。当前检测上报接口没有 `event_id`，不具备请求级幂等：发生 HTTP 超时后，网关必须将结果标记为“发送结果未知”，由现场接入策略决定是否人工核对或接受可能重复的统计，不能盲目重试并假定系统会自动去重。独立摄像头的 `stream_url` 当前仅作为登记信息和后续媒体接入引用；PM 摄像头区显示的是已入库的检测摘要，不会通过此接口接收视频帧。

## 10. 安全、可靠性和异常处理

### 10.1 必须遵守的安全规则

1. 硬件急停的优先级高于任何网络命令。
2. 断网、地图缺失、定位失效、障碍无法绕行时，设备必须按机端策略减速、停车或安全保持。
3. `release` 不能自动恢复运动；设备必须先验证物理安全条件。
4. 设备不得绕过禁行区、速度限制或本体安全状态。
5. 平台的围栏和碰撞命令是集中协调补充，不是设备侧安全功能的替代品。

### 10.2 HTTP 返回处理

| 状态码 | 设备侧处理 |
| --- | --- |
| 200/201 | 成功；保存响应中的设备/命令信息 |
| 304 | 条件读取的地图版本未变化；继续使用本地已验证版本 |
| 401 | 密钥无效或缺失；停止重试并触发本地运维告警 |
| 403 | 设备网关被禁用；停止接入并等待平台授权 |
| 404 | 设备未注册、命令不属于本设备或资源不存在；人工核对设备编码 |
| 409 | 遥测乱序、未知执行 ID、冲突 ACK、项目未初始化或地图版本已变化；按响应 `detail.code` 修正状态后重试 |
| 422 | 请求字段或坐标不合法；修正数据，不应盲目重试 |
| 5xx | 服务端暂时不可用；采用指数退避重试，命令 ACK 和遥测事件保持原 ID |

### 10.3 本地持久化要求

桥接程序至少持久化：设备独立密钥、当前 `boot_id`、最后序列号、已处理命令 ID、未成功提交的 ACK、未成功提交的遥测事件、当前任务 `execution_id`、最后已验证地图的 `sync_revision`、点云 `map_id`、ETag 和实际使用资产的 SHA-256。重启后必须避免重复执行同一命令，也不得把未完成验证的临时地图恢复为运行地图。

## 11. 联调验收清单

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| D01 | 首次注册 | 收到独立设备密钥，设备出现在 O&M 列表 |
| D02 | 心跳遥测 | 位姿、电量、状态在页面和数据库中更新；重复事件不重复写入 |
| D03 | 乱序保护 | 同一启动周期旧序列收到 409 |
| D04 | 任务启动 | `mission_start` 被去重执行，设备上报 `accepted` 和 `running` |
| D05 | 任务完成 | 上报 `completed` 后任务进度为 100%，依赖任务可解锁 |
| D06 | 暂停恢复 | 命令 ACK 后仍等待遥测；实际状态只在 `paused`/`running` 后改变 |
| D07 | 改派 | 旧设备 `cancelled` 前，新设备不收到启动命令 |
| D08 | 急停 | 所有目标设备收到 `estop`，本体保持安全停止 |
| D09 | 点云地图 | 真实点云、区域、点位、网格坐标在 O&M 三维视图一致 |
| D10 | 机器人地图同步 | 专属密钥可获取清单；ETag 未变化返回 304；当前 `map_id` 可下载完整点云；过期版本返回 409；校验后原子切换 |
| D11 | 故障恢复 | 网络中断后可重传遥测和 ACK，命令不会重复实际执行；地图同步失败保留上一份已验证地图 |

## 12. 交付物要求

每个设备型号或 Gazebo 桥接程序应提供：

1. 设备型号、硬件序列号、软件版本和能力清单。
2. 本规范字段到 ROS 话题、Gazebo 状态或厂商 SDK 字段的映射表。
3. 命令处理、去重、持久化、失败码和重连策略说明。
4. 坐标系定义、单位、地图版本和定位精度说明。
5. 心跳、任务、暂停、恢复、取消、急停、恢复和异常注入的联调记录。
6. 安全回路、失联降级和人工接管说明。
