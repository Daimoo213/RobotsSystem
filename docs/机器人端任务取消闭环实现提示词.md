# 机器人端任务取消闭环实现提示词

将以下提示词提供给机器人设备项目的开发人员或代码生成工具使用。它针对机器人端网关/控制适配层，不要求也不包含调度平台、ROS 节点、导航算法或硬件驱动的具体实现。

```text
你正在开发一台机器人设备上的常驻网关程序。请在既有的“平台命令轮询、任务执行状态机、遥测上报”基础上，完整实现 `mission_cancel`（取消已下发任务）闭环。

目标：操作员在平台取消一个任务后，平台为该任务的每个执行单元下发 `mission_cancel`。机器人必须真正停止并清理对应执行单元，再通过遥测确认 `cancelled`。命令 ACK 不等于任务取消完成。

## 平台契约

运行配置由部署环境提供，禁止写入源码或日志：

- `PLATFORM_BASE_URL`
- `DEVICE_CODE`
- `DEVICE_GATEWAY_API_KEY`

命令拉取：

```http
GET {PLATFORM_BASE_URL}/api/devices/gateway/{DEVICE_CODE}/commands
X-Device-Gateway-Key: {DEVICE_GATEWAY_API_KEY}
```

取消命令的关键结构如下，必须以实际响应为准：

```json
{
  "id": "平台命令 UUID",
  "command": "mission_cancel",
  "payload": {
    "execution_id": "此次任务执行实例的唯一标识",
    "reason": "task_cancelled_by_operator"
  }
}
```

命令 ACK：

```http
POST {PLATFORM_BASE_URL}/api/devices/gateway/{DEVICE_CODE}/commands/{command_id}/ack
X-Device-Gateway-Key: {DEVICE_GATEWAY_API_KEY}
Content-Type: application/json
```

成功处理命令后发送：

```json
{
  "status": "acknowledged",
  "message": "mission cancel accepted by local controller"
}
```

无法处理命令时发送：

```json
{
  "status": "failed",
  "message": "具体、可诊断的真实原因"
}
```

任务终态只能由遥测确认。完成安全取消后调用：

```http
POST {PLATFORM_BASE_URL}/api/devices/gateway/{DEVICE_CODE}/telemetry
X-Device-Gateway-Key: {DEVICE_GATEWAY_API_KEY}
Content-Type: application/json
```

遥测必须保留正常的设备真实状态字段，并包含同一 `execution_id`：

```json
{
  "event_id": "新的唯一事件 ID",
  "boot_id": "本次控制器启动周期 ID",
  "sequence": 128,
  "frame_id": "map",
  "status": "idle",
  "observed_at": "2026-08-03T10:20:30+08:00",
  "mission": {
    "execution_id": "取消命令 payload 中的 execution_id",
    "state": "cancelled",
    "progress": 真实的已执行进度,
    "completed_qty": 真实的已完成工作量,
    "result": {
      "cancel_reason": "task_cancelled_by_operator",
      "cancelled_at": "2026-08-03T10:20:30+08:00",
      "safe_stop_confirmed": true
    }
  }
}
```

`event_id` 每次遥测必须不同；同一 `boot_id` 的 `sequence` 必须严格递增。不得为了让平台关闭任务而编造 `status`、位置、进度、完成量或 `cancelled` 状态。若安全停车、属具收回或控制器清理尚未完成，不能报告 `cancelled`。

## 必须实现的行为

1. 命令轮询约每秒一次。机器人空闲、执行、暂停和取消中都不得停止轮询；网络异常时使用有上限的指数退避。
2. 将接收到的命令、ACK 结果、活动 `execution_id`、任务上下文和取消意图持久化到本机可靠存储。设备重启后必须恢复未完成取消，不得重新开始该任务。
3. 使用 `command.id` 做去重。平台采用至少一次投递：同一命令重复到达时，不得再次触发运动或作业动作，只重发已持久化的相同 ACK。对同一 `execution_id` 的重复取消请求也必须幂等。
4. 收到 `mission_cancel` 后，先校验 `payload.execution_id`。它不是当前任务时，不得误取消其他任务；按本机状态记录并返回可诊断结果。已经取消完成的同一执行实例，重发 ACK，并可重发同一真实的 `cancelled` 遥测。
5. 对匹配的活动执行实例，按设备安全顺序执行：停止派发新的导航/作业动作 -> 请求本机控制器取消当前动作 -> 等待移动底盘、属具和作业控制器确认进入安全静止或允许的保持状态 -> 释放本地任务占用、定时器和临时资源 -> 持久化“取消完成”。本机已有的硬件急停和安全策略优先级必须高于本任务取消。
6. 控制器已经接受取消请求后，持久化 ACK 并上报 `acknowledged`。ACK 发送失败、超时或返回 5xx 时，保留待发记录，以相同内容重试；收到成功响应后才清除待发 ACK。
7. 只有第 5 步全部完成后，构造并持久化一条 `mission.state="cancelled"` 遥测，再发送到平台。遥测网络失败时按同一 `event_id` 重试；成功后才清除待发事件。
8. 取消请求已持久化后，禁止对同一 `execution_id` 执行恢复或继续动作。若取消过程失败或无法安全停止，报告真实故障和诊断信息；不要伪报 `cancelled`。
9. 完成取消后，后续普通遥测应反映设备真实状态。仅当机器人确实可接受新工作时才报告 `idle` 或 `ready`；仍在人工接管、故障或急停时必须如实报告对应状态。

## 本地接口边界

请把平台通信与机器人本机控制解耦。定义一个可替换的本地控制适配接口，例如：

- `get_active_execution()`：读取本机持久化的执行上下文；
- `request_cancel(execution_id, reason)`：请求底盘、导航和作业控制器停止；
- `wait_until_safe_stopped(execution_id, timeout)`：只返回真实确认结果；
- `cleanup_execution(execution_id)`：释放本机任务资源；
- `get_actual_device_state()`：读取真实设备状态、位置、健康度和完成量。

不得在网关中伪造导航完成、作业完成、定位、传感器状态或安全确认。机器人具体使用 ROS、厂商 SDK、PLC、串口控制器还是其他实现由设备项目决定；网关只调用其已有的本机控制接口。

## 验收场景

实现后请提供自动化测试或可重复的集成测试，至少覆盖：

1. 执行中的任务收到取消命令：仅停止一次，先 ACK，安全停止完成后上报同一 `execution_id` 的 `cancelled`。
2. 平台重发同一 `command.id`：不重复停止动作，重发完全相同的 ACK。
3. 取消过程中网络中断或网关重启：恢复后继续取消并补发未确认的 ACK/遥测，不丢失取消意图。
4. 取消时本机控制器拒绝或安全停止超时：保留真实诊断，不能上报 `cancelled`。
5. 多机器人协作任务：本设备只取消和上报自己的 `execution_id` 与真实 `completed_qty`，不影响其他设备执行单元。

交付内容：实现代码、配置项说明、持久化模型或迁移、测试、运行日志中的脱敏诊断信息，以及一份说明“命令 ACK”和“遥测 `cancelled`”不同语义的简短接入文档。不要修改调度平台代码，不要把设备网关密钥写入代码仓库。
```
