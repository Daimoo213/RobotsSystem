# 部署与运维手册

## 1. 运行边界

本机开发管理器和完整容器部署不能同时运行，它们使用不同端口和不同数据库卷：

| 模式 | 用途 | PM | O&M | 数据卷 |
| --- | --- | --- | --- | --- |
| 本机开发 | 修改和调试源码 | 5173 | 5174 | `pgdata` / `redisdata` |
| 完整部署 | 局域网持续运行 | 8080 | 8081 | `postgres_data` / `redis_data` |

两个模式的数据不会自动互相复制。这是为了避免开发数据库口令与部署随机口令不一致。需要迁移历史数据时，应先从来源环境导出 PostgreSQL 自定义格式备份，再在目标环境显式恢复。

本机开发管理器启动后端时默认使用 Uvicorn 热重载，并且只监控 `backend/app`，用于源码调试。完整容器部署不启用热重载，避免现场长期运行因文件变化而重启服务。

## 2. 首次部署

要求 Windows 上已安装 Docker Desktop，并且 Docker Engine 正常运行。

### 2.1 发布包部署（推荐）

开发机生成普通发布包：

```powershell
py -3.10 manager\deploy.py package
```

普通包包含部署所需源码，目标机需要能够访问配置好的 Docker 镜像仓库。现场网络不稳定或不能访问镜像仓库时，生成离线包：

```powershell
py -3.10 manager\deploy.py package --offline
```

也可双击 `manager/build_release.bat` 生成离线包。离线包包含当前源码构建出的后端、PM、O&M 镜像以及 PostgreSQL、Redis 运行镜像，因此文件较大，但目标机安装时不访问 Docker Hub。

发布结果保存在 `release/`，文件名包含 `VERSION` 中的 SemVer，每个 ZIP 同时生成 `.sha256` 校验文件。ZIP 不包含 `deploy/.env`、`backend/.env`、数据库、Docker 卷、备份、日志、缓存、`node_modules` 或已有前端构建结果。

目标 Windows 电脑只需安装并启动 Docker Desktop：

1. 复制 ZIP 和对应 `.sha256` 文件到目标机并校验文件。
2. 解压 ZIP，进入生成的 `RobotsSystem` 目录。
3. 右键以管理员身份运行 `install.cmd`。管理员权限只用于创建专用的 Windows 私有网络防火墙规则；非管理员运行仍可安装，但不会自动开放局域网端口。
4. 安装器自动校验发布清单、在 `C:\ProgramData\RobotsSystem\deploy.env` 生成目标机独有密钥、加载离线镜像或拉取版本化 GHCR 镜像、启动五项服务并检查 HTTP 接口。
5. 日常运行 `manage.cmd` 查看状态、启动或修复、重启、保留数据停止以及跟踪日志。

发布包安装不要求 Python、Node.js、pnpm、PostgreSQL 或 Redis。Docker Desktop 是唯一需要预先安装的运行环境。项目资料和 PM/O&M 密码仍须由项目负责人在首次初始化页面填写，安装器不会编造业务数据或默认账号。正式在线发布和升级见 [版本发布与升级](版本发布与升级.md)。

### 2.2 源码命令部署

```powershell
py -3.10 manager\deploy.py init
py -3.10 manager\deploy.py doctor
py -3.10 manager\deploy.py up
```

`init` 创建 `deploy/.env`，其中的数据库、Redis、JWT、设备网关和首次初始化密钥均在本机随机生成，终端不会打印密钥。若文件已经存在，工具拒绝覆盖。

默认监听：

| 服务 | 地址 |
| --- | --- |
| 后端和设备网关 | `http://<部署机IP>:8000` |
| PM | `http://<部署机IP>:8080` |
| O&M | `http://<部署机IP>:8081` |

PostgreSQL 和 Redis 只存在于 Docker 内部网络，不向局域网发布端口。PM/O&M 通过同源 Nginx 代理访问 API 与 WebSocket，浏览器不会访问自己的 `localhost`。

首次打开页面时，在部署机读取 `deploy/.env` 中的 `INITIAL_SETUP_TOKEN`，填写真实项目和 PM/O&M 账号。该令牌不是账号密码，项目初始化完成后再次调用初始化接口会被拒绝。

## 3. 健康与状态

```powershell
py -3.10 manager\deploy.py status
py -3.10 manager\deploy.py logs --tail 200
py -3.10 manager\deploy.py logs backend --follow
```

部署只有在以下条件同时满足时才算健康：

- PostgreSQL 能执行查询。
- Redis 能响应 `PING`。
- 后端 `/ready` 返回 200。
- PM/O&M 的 Nginx 能通过代理访问 `/api/auth/setup-status`。

`status` 在容器缺失、停止或不健康时返回非零退出码，可用于自动化检查。

各容器使用 Docker `json-file` 日志驱动，单文件最大 10 MiB、最多保留 5 个文件，避免长期运行无限占用系统盘。

## 4. 停止与重启

```powershell
py -3.10 manager\deploy.py restart backend
py -3.10 manager\deploy.py down
```

`down` 使用 60 秒停止宽限期并保留数据库、Redis、备份卷。它不会执行 `down -v`。除非已经完成并验证备份，否则不要手工删除 Docker 卷。

## 5. 升级

代码更新后执行：

```powershell
py -3.10 manager\deploy.py doctor
py -3.10 manager\deploy.py up
```

如果部署数据库正在运行，`up` 会先在 `deploy/backups/` 生成 PostgreSQL 自定义格式备份，然后重新构建镜像。后端容器只有在 PostgreSQL/Redis 健康后才执行 Alembic 迁移；迁移失败时后端不会进入健康状态，PM/O&M 也不会启动为可用状态。

## 6. 备份与恢复

手工备份：

```powershell
py -3.10 manager\deploy.py backup
```

备份文件保存在部署机 `deploy/backups/`，不会提交到仓库。应定期复制到受控存储，并验证可恢复性。

恢复会覆盖当前数据库，必须明确确认：

```powershell
py -3.10 manager\deploy.py restore deploy\backups\robots_system_<time>.dump --confirm RESTORE
```

恢复前工具停止后端和双前端。恢复失败时应用保持停止，避免在不完整数据库上继续写入；排查后可重新执行恢复或 `up`。

## 7. 局域网安全

- `deploy/.env`（源码部署）或 `C:\ProgramData\RobotsSystem\deploy.env`（发布包部署）只允许部署管理员读取，不通过聊天、截图或前端传递。
- `JWT_SECRET`、`DEVICE_GATEWAY_API_KEY`、`INITIAL_SETUP_TOKEN`、数据库密码和 Redis 密码必须不同。
- 防火墙只开放实际需要的 8000、8080、8081；设备网关需要 8000，普通浏览器只需 PM/O&M 端口。
- `DEBUG` 在完整部署中固定为 `false`。
- 真机急停、安全继电器、避障和硬件授权必须独立于本平台。

## 8. 账号恢复

系统不依赖公网邮件找回。仍有 O&M 管理账号时，应由管理员创建或管理账号；所有账号都无法登录时，在部署机交互式重置：

```powershell
py -3.10 manager\deploy.py list-users
py -3.10 manager\deploy.py reset-password <username>
```

新密码通过隐藏输入读取，不出现在命令行历史中。重置完成会递增账号认证版本，使该账号以前签发的 JWT 全部失效。`INITIAL_SETUP_TOKEN` 不能用于密码恢复。

## 9. 故障排查

1. 执行 `deploy.py doctor` 检查 Docker、Compose 和密钥占位符。
2. 执行 `deploy.py status` 找出未健康服务。
3. 查看对应服务日志，后端启动失败优先检查迁移、PostgreSQL和Redis。
4. 端口被其他程序占用时，先确认该进程归属，不要直接强制终止未知进程。
5. 数据库恢复或迁移异常时保持应用停止，使用最近一次已验证备份恢复。
6. 若预检提示 Docker Hub 不可达，应在 Docker Desktop 配置现场网络允许的 HTTPS 代理或镜像仓库并重启 Docker Engine；不要反复执行部署掩盖镜像拉取失败。
