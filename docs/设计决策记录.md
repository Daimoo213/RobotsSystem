# 机器人智能集群调度系统设计决策记录

本文只记录会影响后续开发与验收的稳定决策。当前完成度、测试数量和本机运行状态记录在 `开发进度.md`，使用与接入步骤记录在对应手册，避免同一事实多处维护。

## UI-OM-001：底部设备条布局

- 日期：2026-07-30
- 状态：生效
- 背景：底部设备卡片曾因五项健康指标使用四列布局而换行，内容被卡片边界和滚动条裁切。
- 决定：设备条必须处于页面正常布局流中，不覆盖左右侧栏；单卡尺寸和三行信息轨道保持稳定；五项健康指标始终单行显示；设备较多时横向滚动并展示全部设备，不静默截断数量。
- 验收：目标桌面视口中卡片不越界、不垂直裁切，横向滚动条不覆盖内容，长设备编码截断但可通过标题查看，当前选中设备有明确反馈。

## DATA-DEV-001：设备在线与健康状态

- 日期：2026-07-30
- 状态：生效
- 背景：设备停止上报后，旧业务状态和旧健康值曾继续显示为“在线、待机、正常”。
- 决定：在线状态由最后心跳和服务端 TTL 派生，离线优先于待机、作业等业务状态。设备离线后连接项显示故障，其余实时健康项显示未知，电量明确标为末次上报值；健康字段缺失不得默认显示正常。
- 验收：超过心跳阈值的设备显示离线，不再出现离线设备仍呈现实时正常健康状态的情况。

## DATA-MAP-001：完整点云地图上传

- 日期：2026-07-30

- 决定：扫描建图设备在设备侧完成融合与抽样，平台接收完整点云地图的替换上传。后端和前端不再聚合多个点云快照。仅在项目建图开关开启时允许上传。

## DATA-MAP-002：机器人地图同步

- 日期：2026-07-31
- 状态：生效
- 背景：操作员地图读取接口使用 JWT，设备专属密钥此前只能上报遥测和拉取命令，机器人无法安全发现并下载当前地图。
- 决定：机器人使用本设备独立网关密钥获取轻量地图同步清单，再按清单中的不可变 `map_id` 下载完整点云。清单包含真实区域、点位、资产引用、统一坐标系、点云摘要和基于持久化内容计算的整图修订号，不在任务命令中传输点云。
- 项目边界：当前数据库模型按单项目运行；所有已注册且启用的设备属于该唯一项目并可读取全站地图。项目记录不唯一或没有唯一活动项目时拒绝同步，不把全局地图表猜测归属到任一项目。
- 一致性：设备下载到临时位置并校验坐标系、版本、点数、结构和资产 SHA-256；下载完成后再次确认清单修订号，只有修订号未变化时才能原子切换。校验或复查失败时保留上一份已验证地图并进入机端安全降级，不得半量覆盖运行地图。
- 验收：WHEN 已注册且启用的设备提供本机专属密钥 THEN 平台返回当前真实地图清单；WHEN `ETag` 未变化 THEN 平台返回 304；WHEN 请求的 `map_id` 已过期 THEN 平台返回 409 并要求重新同步；IF 持久化地图坐标系与项目不一致 THEN 平台拒绝下发混合坐标数据。

## DATA-MAP-003：机器人通行路径与坡道约束

- 日期：2026-08-03
- 状态：生效
- 决定：O&M 维护真实测绘或现场确认的机器人通行路径。每条路径使用同一 `map_frame` 内按顺序排列的 `[x, y, z]` 点列，`z` 是高程；相邻点据此表示上坡或下坡。路径同时声明单向/双向规则、最小净宽、最大坡度、适用设备类型和启用状态。
- 数据质量：服务端拒绝非三维或非有限坐标、相邻点水平重合的垂直段、重复设备类型，以及实际坡度超过声明上限的路径。空设备类型列表表示平台不按设备类型限制，但不能替代设备本体的尺寸、坡度、安全与避障校验。
- 同步与边界：路径随设备专属 `map-sync` 清单下发，并参与 `sync_revision` 与 ETag 计算；路径变化后设备必须重新比较清单再原子切换本地可用地图。平台不实现 ROS/Nav2 寻路、局部避障、坡面通行控制或本体安全回路。

## SCOPE-001：机器人侧实现边界

- 日期：2026-07-30
- 状态：生效
- 决定：本仓库完成 PM/O&M 前端、后端、数据库和设备网关接口，不实现机器人 ROS 节点、固件、SLAM、导航、局部避障或本体安全回路。真机或 Gazebo 桥接程序按设备网关协议接入。

## TASK-EXEC-001：任务等待、作业与返航闭环

- 日期：2026-07-31
- 状态：生效
- 背景：原调度器在无候选设备时只保留内存中的待办，没有持久化等待原因；任务命令只有目标坐标和工序编码，无法表达作业参数、返回点以及“返回后才完成”。
- 数据事实源：数据库任务是唯一事实源。调度器每个周期从数据库重建依赖视图；没有合适设备时任务保持 `pending`，并持久化 `dispatch_state=waiting_device` 和稳定原因码。候选设备后续上线、空闲或电量恢复后，任务自动重新参与派发，不要求人工重建任务。
- 候选资格：设备必须已启用、心跳有效、处于 `idle/ready`、电量达到阈值、没有活动执行实例，并明确声明支持任务工序；设备类型必须同时兼容作业点和返回点。结构化作业或返航任务只派给注册为 v2 的设备。
- 并发保证：派发事务锁定任务和入选设备；数据库只保留“每台设备最多一个活动执行”的部分唯一索引。一个业务任务可并发拥有多个执行单元，但同一设备不会收到重复 `mission_start`。
- v2 编排：平台下发目标点、项目地图坐标系、结构化作业参数、限制条件和明确返回点。执行阶段依次为 `preparing`、`navigating_to_target`、`arrived_at_target`、`working`、`work_completed`，需要返回时继续为 `returning`、`returned`。
- 完成规则：v2 遥测使用连续递增的 `phase_sequence`。同一阶段的进度变化也必须递增序号；相同序号只允许完全相同的幂等重传。返航任务只有报告 `state=completed`、`phase=returned`，并提供匹配返回点的完成证据后，平台才完成任务并解锁依赖任务。
- 设备状态边界：终态执行只释放平台中的活动执行占用，不推测机器人已待机。机器人必须真实上报 `idle/ready` 后才能再次承接任务。
- 机器人侧边界：路径规划、避障、到点判定、具体作业动作和安全返航仍由机器人 ROS/Nav2、厂商 SDK 或 Gazebo 桥接器实现。
- 验收：WHEN 暂无合适设备 THEN 平台 SHALL 持久化等待状态并持续重试；WHEN 资源需求均被覆盖 THEN 平台 SHALL 为每台入选设备创建一个执行单元并派发；WHEN 返航尚未确认 THEN 平台 SHALL 拒绝完成；WHEN 返回阶段和返回点证据匹配且所有完成门槛达量 THEN 平台 SHALL 完成任务并释放后续依赖。

## TASK-RESOURCE-001：基于真实产能的多设备协同规划

- 日期：2026-07-31
- 状态：生效
- 背景：业务任务可能同时需要不同类型的设备，例如开挖与转运。仅按任务主工序选择单台设备会遗漏辅助工序，也无法根据交付量和计划窗口估算所需设备数量。
- 事实源：设备网关声明带来源、证据、上报时间和有效期的单位产能；任务保存真实交付量、计划起止时间和一个或多个资源需求。未登记有效产能的设备不得计入工作量覆盖，平台不得使用默认速率或前端演示数据填补。
- 决定：一个业务任务由资源需求、资源计划和设备执行单元组成。规划器对每个资源需求按能力、单位、在线、空闲、电量、地图点位兼容性、协议版本和有效产能筛选设备，按可交付量优先累计至目标量。辅助资源需求按自身能力编码匹配，不能被任务主工序过滤掉。
- 派发与完成：所有完成门槛需求覆盖后，派发事务创建多个执行单元；每个 `mission_start` 只包含本设备配额和真实作业范围。设备遥测的 `completed_qty` 只更新所属执行单元，平台聚合后更新任务完成量；单台设备完成不代表业务任务完成，失败或取消时对剩余量重新规划。
- 前端：PM 任务详情展示按设备类型汇总的计划数量、可用数量、计划产能、产能覆盖率、缺口原因，以及每台设备的配额、完成量、状态和执行阶段。实时消息与 REST 使用相同的任务数据形状，避免资源计划字段在刷新中丢失。
- 验收：WHEN 多个资源角色均有覆盖 THEN 系统派发各自所需设备类型和数量；WHEN 任一角色缺少有效产能 THEN 任务保持等待产能；WHEN 其中一个执行单元完成 THEN 任务仅聚合进度而不提前完成；WHEN 所有完成门槛均达量且返航条件满足 THEN 任务完成。

## DATA-001：真实数据原则

- 日期：2026-07-30
- 状态：生效
- 决定：不使用前端随机数据、模拟业务数据、启动种子数据或为展示编造的数据库数据。展示数据只能来自项目人员录入、真实设备运行、真实外部算法服务或 Gazebo 等外部仿真运行结果。

## COORD-001：项目地图坐标系

- 日期：2026-07-30
- 状态：生效
- 决定：项目 `map_frame` 采用固定右手笛卡尔坐标系，单位为米。`+Z` 竖直向上；从 `+Z` 俯视时，`+Y` 位于 `+X` 逆时针 90°。原点与 `+X` 现场基准方向在项目联调时固定，完整地图替换不得改变。所有设备、点云和地图资产必须在上传前转换到该坐标系。
- 实现约束：后端拒绝与项目 `map_frame` 不一致的遥测、校准、点云和地图资产；O&M 使用 `(x_three,y_three,z_three)=(x_map,z_map,-y_map)` 转换到 Three.js 坐标，保持右手性。
