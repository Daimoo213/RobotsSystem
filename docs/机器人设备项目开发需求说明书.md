# 机器人设备接入项目需求说明书

用途：作为 AICode 或其他编码智能体从零创建机器人设备侧项目时的开发输入。

版本：v1

## 1. 开发背景

施工现场存在运输、巡检、挖掘、吊装和施工作业等不同机器人或工程设备。每台设备有自己的控制程序，但需要通过统一接口接收上位任务、报告实际运行状态，并在断网、重启、重复命令和急停等情况下保持可追溯和安全。

本设备项目要开发一个可独立部署的设备控制与接入程序。程序连接设备实际运行环境，将运行过程产生的状态转换为统一 HTTP JSON 遥测，同时从上位调度服务拉取命令并交给设备执行。

数据来源只有一条原则：发送给上位调度服务的业务数据必须来自设备实际运行过程。不得由前端、网关或设备程序随机生成设备、位置、电量、进度、点云、检测结果或任务完成状态。

## 2. 项目目标

设备项目完成后必须能够：

1. 使用唯一设备编码完成首次注册并安全保存设备专属密钥。
2. 周期性上报实际心跳、状态、位置、电量、健康信息和运行指标。
3. 可靠拉取、去重和执行上位命令。
4. 对命令给出可重试的 ACK，并通过遥测报告任务的实际状态。
5. 在程序重启或网络中断后恢复未完成的遥测、ACK 和任务上下文。
6. 正确处理暂停、恢复、取消、急停和安全释放。
7. 根据设备具备的真实能力选择性接入校正、地图、点云或视觉接口。
8. 通过联调验收后可作为长期运行的设备侧服务部署。

## 3. 项目范围

本设备项目负责：

- 读取设备控制程序或运行环境的实际状态；
- 将设备状态映射为统一遥测协议；
- 调用上位调度服务的设备网关接口；
- 将上位命令转换为设备可执行动作；
- 保存密钥、命令去重记录、事件序号和待发送数据；
- 输出结构化运行日志和可诊断错误；
- 执行本地安全检查和断网降级策略。

本设备项目不负责：

- 上位任务编排、跨设备分配或项目看板；
- 伪造暂时不可获取的设备指标；
- 用网络急停替代设备本体安全回路；
- 未经设备实际执行就报告任务完成。

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| 设备控制器 | 直接控制机器人运动或作业的程序 |
| 接入程序 | 本项目开发的设备侧 HTTP 网关程序 |
| 上位调度服务 | 分配任务、保存设备状态并下发命令的外部服务 |
| 共享网关密钥 | 对应 `DEVICE_GATEWAY_API_KEY`；用于首次创建设备，也用于地图、点云和摄像头网关接口 |
| 设备专属密钥 | 首次注册成功后返回、后续由单台设备使用的 `device_gateway_key` |
| 遥测事件 | 设备一次实际状态采样及其任务状态 |
| 命令 ACK | 设备对某条命令处理结果的确认，不等同于任务完成 |
| execution_id | 一次任务在一台设备上的执行实例标识 |

## 5. 最小软件结构

AICode 应按职责拆分代码，至少包含以下模块：

| 模块 | 职责 |
| --- | --- |
| `config` | 加载并校验连接地址、设备身份、周期和超时配置 |
| `runtime_adapter` | 读取设备实际状态并执行设备动作 |
| `gateway_client` | 封装注册、遥测、命令和 ACK HTTP 调用 |
| `telemetry_worker` | 采样、编号、持久化和发送遥测 |
| `command_worker` | 拉取、去重、执行和确认命令 |
| `mission_state` | 保存当前 execution_id 和任务状态机 |
| `local_store` | 持久化密钥以外的运行状态、待发队列和去重记录 |
| `safety` | 本地急停、失联、安全释放和人工接管判断 |
| `logging` | 输出不包含密钥的结构化日志 |

`runtime_adapter` 是设备差异的唯一主要入口。HTTP 协议、重试、幂等和任务状态机不得散落到具体设备驱动中。

建议的最小适配接口：

```text
get_runtime_snapshot() -> RuntimeSnapshot
execute_command(command, payload) -> CommandResult
get_mission_update(execution_id) -> MissionUpdate | None
request_calibration(target) -> CalibrationResult
is_safe_to_release() -> bool
```

返回值必须来自实际执行结果，不能返回随机占位值。

## 6. 必需配置

所有环境差异必须配置化，不得把地址或密钥写死在代码中。

| 配置项 | 必需 | 说明 |
| --- | --- | --- |
| `UPSTREAM_BASE_URL` | 是 | 上位服务地址，例如 `http://192.168.1.10:8000/api` |
| `DEVICE_CODE` | 是 | 设备唯一编码，注册后不得随意变更 |
| `DEVICE_NAME` | 是 | 设备显示名称 |
| `DEVICE_TYPE` | 是 | 设备类型编码，用于任务匹配 |
| `DEVICE_MODEL` | 否 | 厂商或型号标识 |
| `DEVICE_CAPABILITIES` | 是 | 设备实际支持的工序和能力 |
| `DEVICE_GATEWAY_API_KEY` | 按需 | 上位服务配置的共享网关密钥；首次注册必需，使用地图、点云或摄像头接口时也必须提供。只允许从环境变量或安全存储读取，不得写死实际值 |
| `DEVICE_GATEWAY_KEY` | 注册后 | 设备专属密钥，必须从安全存储读取 |
| `TELEMETRY_INTERVAL_SECONDS` | 是 | 遥测周期，建议 1 至 5 秒 |
| `COMMAND_POLL_INTERVAL_SECONDS` | 是 | 命令拉取周期 |
| `HTTP_TIMEOUT_SECONDS` | 是 | 单次 HTTP 请求超时 |
| `LOCAL_STORE_PATH` | 是 | 本地持久化文件或数据库路径 |

日志、异常和诊断接口不得输出任何网关密钥。

## 7. 通信总则

| 项目 | 要求 |
| --- | --- |
| 协议 | HTTP 或 HTTPS |
| 基础路径 | `<UPSTREAM_BASE_URL>`，已包含 `/api` |
| 内容类型 | `application/json` |
| 字符编码 | UTF-8 |
| 时间 | 带时区的 ISO 8601，推荐 UTC `Z` |
| 坐标系 | 默认 `map` |
| 长度单位 | 米 |
| 电量单位 | 百分比 0 至 100 |
| 进度单位 | 百分比 0 至 100 |
| 网关协议版本 | `v1` |
| 命令投递 | 至少一次，必须按命令 ID 去重 |

设备端应保持系统时间同步。`observed_at` 必须使用真实采样时间，不得使用固定时间或无时区时间。

## 8. 首次注册

### 8.1 请求

```http
POST /devices/gateway/register
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
Content-Type: application/json
```

```json
{
  "code": "AGV-101",
  "name": "Material AGV 101",
  "type": "agv",
  "model": "VENDOR-AGV-3",
  "protocol_version": "v1",
  "capabilities": {
    "processes": ["material_transport"],
    "max_speed_mps": 1.2
  },
  "section_tags": {"section": "A"},
  "permissions": {"travel": true, "work": true},
  "section_id": "A",
  "health": {"connection": "ok"}
}
```

`capabilities.processes` 只能声明设备实际能够完成的工序。虚报能力会导致设备收到无法执行的任务。

### 8.2 响应处理

首次创建成功时，响应包含：

```json
{
  "created": true,
  "device": {"code": "AGV-101"},
  "device_gateway_key": "仅首次返回的设备专属密钥"
}
```

接入程序必须在返回成功后原子保存 `device_gateway_key`。如果保存失败，不得继续进入日常运行，应报告人工处理。

### 8.3 更新注册资料

同一 `code` 再次调用注册接口时，请求头必须使用设备专属密钥。共享引导密钥不能更新已注册设备。

更新只用于设备名称、型号、能力、区域或权限发生真实变化时，不应在每次启动时无条件覆盖。

## 9. 遥测上报

### 9.1 接口

```http
POST /devices/gateway/{device_code}/telemetry
X-Device-Gateway-Key: <DEVICE_GATEWAY_KEY>
```

### 9.2 请求示例

```json
{
  "event_id": "AGV-101-20260722-000042",
  "boot_id": "AGV-101-boot-20260722T010000Z",
  "sequence": 42,
  "frame_id": "map",
  "schema_version": "v1",
  "observed_at": "2026-07-22T01:00:05Z",
  "status": "moving",
  "battery": 76.5,
  "position": {"x": 83.2, "y": 132.8, "z": 0.0},
  "section_id": "A",
  "health": {
    "location": "ok",
    "battery": "ok",
    "task": "ok",
    "safety": "ok"
  },
  "metrics": {
    "power_kw": 4.2,
    "energy_kwh_total": 18.7,
    "mileage_km_total": 4.8,
    "runtime_hours_total": 12.3,
    "payload_ratio": 0.55,
    "localization_drift_meters": 0.08
  }
}
```

### 9.3 必须遵守的编号规则

- `event_id`：本设备内唯一；相同事件重传必须沿用原值。
- `boot_id`：每次接入程序或设备控制器重启后生成新值。
- `sequence`：同一 `boot_id` 内从 0 或 1 开始严格递增。
- 只有服务端确认接收后，待发事件才可从本地队列删除。
- HTTP 超时表示结果未知，应使用相同 `event_id` 重试，不得生成新事件。

相同 `event_id` 重传会得到幂等成功。同一 `boot_id` 中旧的或重复的 `sequence` 会返回 409。

### 9.4 状态要求

设备空闲且可接受任务时必须报告 `idle` 或 `ready`。执行过程中可报告 `assigned`、`moving`、`working`、`paused`、`charging`、`fault` 或 `maintenance` 等明确状态。

任务终止且设备恢复可调度条件后，应重新报告 `idle` 或 `ready`。设备离线、故障或安全条件不满足时不得报告可调度状态。

上位调度通常只选择近期有心跳、状态为 `idle` 或 `ready`、电量不低于 20 且能力匹配的设备，因此状态和能力必须准确。

### 9.5 指标缺失

无法从实际运行环境获取的可选指标应省略，不得填 0、固定值或随机值。真实值为 0 时可以上报 0。

## 10. 命令拉取

### 10.1 接口

```http
GET /devices/gateway/{device_code}/commands
X-Device-Gateway-Key: <DEVICE_GATEWAY_KEY>
```

响应包含未终结命令：

```json
{
  "device_code": "AGV-101",
  "global_estop_active": false,
  "commands": [
    {
      "id": "c4cd9e5b-1d1d-4f9b-a3c0-39cdd868cd0e",
      "command": "mission_start",
      "payload": {},
      "created_at": "2026-07-22T01:00:00Z",
      "idempotency_key": "scheduler:...",
      "priority": 50
    }
  ]
}
```

命令可能被重复返回。设备端必须持久化已处理命令 ID，程序重启后仍不能重复执行同一命令。

当 `global_estop_active` 为 true 时，设备必须保持本地安全停止；命令列表中会包含对应的高优先级 `estop` 命令。

### 10.2 支持的命令

| 命令 | 设备侧行为 |
| --- | --- |
| `mission_start` | 保存 execution_id，校验目标和安全条件，开始任务 |
| `mission_pause` | 安全暂停指定任务，实际暂停后上报 `paused` |
| `mission_resume` | 恢复指定任务，实际恢复后上报 `running` |
| `mission_cancel` | 安全终止并清理指定任务，完成后上报 `cancelled` |
| `pause` | 执行设备级暂停 |
| `resume` | 执行设备级恢复，但不得绕过安全检查 |
| `estop` | 立即进入本地安全停止状态 |
| `release` | 仅在本地确认安全后解除保持，不自动恢复运动 |
| `reset` | 按设备约束执行控制器重置 |
| `reset_pose` | 执行定位重置，并通过校正接口报告结果 |

未知命令不得执行，应记录错误并 ACK 为 `failed`。

## 11. 命令 ACK

### 11.1 接口

```http
POST /devices/gateway/{device_code}/commands/{command_id}/ack
X-Device-Gateway-Key: <DEVICE_GATEWAY_KEY>
```

```json
{
  "status": "acknowledged",
  "message": "command accepted by device controller"
}
```

`status` 只能是 `acknowledged` 或 `failed`。

ACK 规则：

1. ACK 必须在设备已经处理命令后产生，不能在拉取到命令时立即无条件成功。
2. ACK 表示命令处理结果，不表示整个任务已经完成。
3. 任务实际状态必须通过遥测中的 `mission` 上报。
4. ACK HTTP 请求失败时，使用同一状态重复发送。
5. 相同终态 ACK 可幂等重试；同一命令提交相反终态会返回 409。

## 12. 任务执行状态

### 12.1 mission_start 载荷

任务启动命令的 `payload` 包含：

```json
{
  "execution_id": "上位服务生成的执行标识",
  "task_id": "任务 UUID",
  "task_code": "T-12345678",
  "process_id": "material_transport",
  "target": {"x": 83.2, "y": 132.8, "z": 0.0},
  "constraints": {}
}
```

设备必须以 `execution_id` 作为任务执行主键，不能自行替换。

### 12.2 遥测中的任务状态

```json
{
  "mission": {
    "execution_id": "上位服务生成的执行标识",
    "state": "running",
    "progress": 32.5,
    "completed_qty": 18.0,
    "estimated_completion_at": "2026-07-22T02:00:00Z",
    "result": {},
    "failure_code": null
  }
}
```

允许上报的状态：

- `accepted`：设备已接受并保存任务；
- `running`：设备已实际开始执行；
- `paused`：设备已实际进入暂停；
- `completed`：设备已实际完成任务；
- `failed`：任务无法完成；
- `cancelled`：设备已安全取消并完成清理。

正常状态流：

```text
accepted -> running -> completed
                    -> paused -> running
                    -> failed
                    -> cancelled
```

终态 `completed`、`failed`、`cancelled` 不可逆。失败时必须提供稳定的 `failure_code`，并在 `result` 中提供可诊断信息。

不得把收到 `mission_start`、发送 ACK 或开始准备动作直接报告为 `completed`。

## 13. 暂停、恢复和改派

- 收到 `mission_pause` 后，先执行安全减速或停机；实际停止后再上报 `paused`。
- 收到 `mission_resume` 后，重新检查安全条件；实际恢复后再上报 `running`。
- 收到 `mission_cancel` 后，终止动作并清理任务；完成后再上报 `cancelled`。
- 上位服务在改派时会等待原设备报告 `cancelled`，随后才会向新设备下发任务。
- 接入程序必须保存待处理控制动作，重启后不得丢失暂停或取消意图。

## 14. 校正结果上报

设备支持定位校正时使用：

```http
POST /devices/gateway/{device_code}/calibration
X-Device-Gateway-Key: <DEVICE_GATEWAY_KEY>
```

```json
{
  "event_id": "AGV-101-calibration-0001",
  "qrcode_id": "A-START-01",
  "source": "automatic",
  "observed_at": "2026-07-22T01:05:00Z",
  "success": true,
  "position": {"x": 83.2, "y": 132.8, "z": 0.0},
  "drift_meters": 0.06,
  "message": "calibration completed"
}
```

`source` 只能是 `automatic` 或 `manual`。`event_id` 用于幂等重试。接口只报告实际校正结果，不能代替设备执行定位校正。

## 15. 可选数据接口

只有设备实际具备对应能力时才接入以下接口。

### 15.1 地图资产

```http
POST /map/gateway/assets
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

必需字段包括 `event_id`、`source_id`、`asset_type`、`asset_uri`、`frame_id` 和 `observed_at`。`asset_type` 为 `mesh_gltf`、`octomap` 或 `geojson`。`asset_uri` 只接受绝对 HTTPS 或 `s3`、`gs`、`oss` 对象存储 URI。

该接口按 `event_id` 幂等，使用共享网关密钥，不使用设备专属密钥。

### 15.2 点云快照

```http
POST /pointcloud/gateway/snapshots
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

每次请求包含 `event_id`、`source_id`、`frame_id`、`observed_at`、`points` 和可选 `metadata`。每个点必须为 `[x,y,z]`，单次 1 至 50,000 点。

该接口按 `event_id` 幂等，使用共享网关密钥。

### 15.3 摄像头和检测结果

```http
POST /cameras/gateway/register
POST /cameras/gateway/{camera_code}/detections
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

检测结果包含检测时间、设备数量、人员数量、扬尘等级、边坡风险和合规率，所有字段必须来自实际运行结果。

摄像头检测上报当前没有 `event_id`，不具备请求级幂等。发生 HTTP 超时后不得盲目重试并假定不会重复，应记录“结果未知”并由接入策略处理。

## 16. HTTP 错误与重试

| 状态码 | 设备侧处理 |
| --- | --- |
| 200/201 | 保存成功结果，确认本地待发记录 |
| 401 | 密钥缺失或无效；停止高频重试并报警 |
| 403 | 设备网关被禁用；停止接入并等待授权 |
| 404 | 设备、命令或资源不存在；核对设备编码和本地上下文 |
| 409 | 序号乱序、execution_id 不匹配或 ACK 冲突；不得无脑重试 |
| 422 | 字段、范围、时间或坐标格式错误；修正数据后重试 |
| 5xx | 服务暂时不可用；采用有上限的指数退避重试 |

退避必须加入小幅随机抖动以避免多设备同时重连，但不得借此生成任何业务数据。重试期间应保持本地待发记录和原有幂等 ID。

## 17. 本地持久化要求

接入程序至少持久化：

- 当前设备专属密钥的安全引用；
- 当前 `boot_id` 和最后使用的 `sequence`；
- 已生成但未确认的遥测事件；
- 已处理命令 ID 及最终处理结果；
- 已生成但未确认的 ACK；
- 当前 `execution_id`、任务状态和任务必要上下文；
- 未完成的暂停、恢复、取消或急停处理状态。

写入必须采用事务或原子替换。程序崩溃时不能出现“设备已执行命令，但去重记录未保存”而导致重启后重复执行。

去重记录保留时间必须覆盖命令可能重投的时间；不允许每次启动清空。

## 18. 安全要求

1. 本地硬件或控制器急停的优先级高于所有网络命令。
2. 断网、定位失效、障碍无法处理或控制器故障时，设备按本地策略减速、停车或保持安全状态。
3. `release` 只解除安全保持，不得自动恢复上一次运动。
4. 设备必须在本地确认环境安全后才 ACK `release` 为成功。
5. 网络命令不得绕过速度限制、禁行规则、碰撞保护或人工接管。
6. 上位服务不可用时，设备不能伪造进度维持在线状态。
7. 密钥不得写入源码、日志、崩溃转储或公开配置文件。

## 19. 日志要求

每条关键日志至少包含：

- UTC 时间；
- 设备编码；
- 事件类型；
- `event_id`、`command_id` 或 `execution_id`；
- HTTP 状态或设备执行结果；
- 可诊断错误码。

必须记录注册、遥测失败、命令收到、去重命中、执行开始、执行结果、ACK 结果、任务状态变化、断网重连、急停和安全释放。

日志不得包含请求头中的密钥或完整敏感配置。

## 20. AICode 实现约束

AICode 生成代码时必须遵守：

1. 先实现接口客户端、持久化和状态机，再接入具体设备运行适配器。
2. 所有 HTTP 调用集中封装，业务模块不得自行拼接请求。
3. 所有命令先持久化再执行，所有 ACK 和遥测先持久化再发送。
4. 所有重试复用原 `event_id`、`command_id` 或 ACK 终态。
5. 使用类型化请求模型和显式字段校验，不使用任意字符串拼接 JSON。
6. 生产启动入口不得包含随机设备状态、随机任务进度或自动演示循环。
7. 无法获取的可选字段省略，不设置看似合理的默认业务值。
8. 密钥使用环境变量或系统安全存储，日志统一脱敏。
9. 停止进程时先停止拉取新命令，再保存当前状态并完成可控退出。
10. 每个接口和状态转换都要有自动化测试。

## 21. 联调验收

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| D01 | 首次注册 | 成功保存设备专属密钥，重复启动不再次使用引导密钥更新设备 |
| D02 | 遥测 | 实际状态、位置、电量进入上位服务，相同 event_id 重传不重复 |
| D03 | 序号 | 同一 boot_id 乱序 sequence 被识别并正确处理 |
| D04 | 命令去重 | 相同 command.id 多次返回时设备动作只执行一次 |
| D05 | ACK 重试 | 网络中断后重复相同 ACK 可成功，不产生冲突结果 |
| D06 | 任务开始 | mission_start 后依次报告 accepted 和实际 running |
| D07 | 任务完成 | 只有实际完成后才报告 completed 和真实完成量 |
| D08 | 暂停恢复 | 实际暂停后报告 paused，实际恢复后报告 running |
| D09 | 取消改派 | 原设备完成取消并报告 cancelled，不继续执行旧任务 |
| D10 | 急停释放 | 急停立即进入安全状态，release 不自动恢复运动 |
| D11 | 重启恢复 | 执行中重启后恢复 execution_id、去重记录和待发数据 |
| D12 | 断网恢复 | 断网期间保持本地安全，恢复后按原 ID 补发而不伪造状态 |

可选接口只有启用时才验收，但一旦启用，数据真实性、认证和幂等规则同样必须通过。

## 22. 最小交付物

设备项目最终至少交付：

1. 可运行的设备接入程序源码；
2. 配置模板和配置项说明，不包含真实密钥；
3. 安装、启动、停止和升级说明；
4. 设备运行适配器及字段映射说明；
5. 本地持久化结构和迁移方案；
6. 命令、任务状态和错误码说明；
7. 自动化测试和 D01-D12 联调记录；
8. 运行日志位置及故障排查说明。

## 23. 开发前必须确认的信息

开始编写具体设备适配器前，只需确认以下必要信息：

- 上位调度服务基础地址；
- 首次注册引导密钥的安全交付方式；
- 设备唯一编码、名称、类型和实际工序能力；
- 从设备运行环境读取状态和执行命令的调用方式；
- 坐标系、时间源和状态字段的映射；
- 本地安全停止、人工接管和安全释放条件；
- 接入程序的安装位置和本地持久化路径。

未确认的信息必须保留为配置或接口，不得由 AICode 自行编造业务值。
