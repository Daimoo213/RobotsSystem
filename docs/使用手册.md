# 机器人智能集群调度系统使用手册

## 1. 系统边界

系统包含 PM 项目调度端、O&M 运维端和 FastAPI 控制后端。它负责保存真实项目数据、调度任务、向设备写入命令队列并展示设备回传的数据。

机器人本体、ROS、固件、SLAM、导航、局部避障与 Gazebo 场景在仓库外实现。真机或 Gazebo 桥接程序通过后端接口接入。

## 2. 启动

本机开发使用 `manager.py`，局域网完整部署使用 `deploy.py`。两者不能同时运行。

开发管理器启动后，同一私有局域网内可通过 `http://<开发机IP>:5173` 访问 PM、通过 `http://<开发机IP>:5174` 访问 O&M，机器人或外部仿真桥通过 `http://<开发机IP>:8000` 接入。Windows 防火墙只需对 Private 网络开放 `5173`、`5174`、`8000`；PostgreSQL `5432` 与 Redis `6379` 不应开放。

### 2.1 本机开发

```powershell
py -3.10 manager\manager.py init-env
py -3.10 manager\manager.py doctor
py -3.10 manager\manager.py start all
```

| 应用 | 地址 |
| --- | --- |
| API / Swagger | `http://127.0.0.1:8000` / `http://127.0.0.1:8000/docs` |
| PM | `http://127.0.0.1:5173` |
| O&M | `http://127.0.0.1:5174` |

停止：`py -3.10 manager\manager.py stop all`。

### 2.2 局域网完整部署

```powershell
py -3.10 manager\deploy.py init
py -3.10 manager\deploy.py doctor
py -3.10 manager\deploy.py up
```

| 应用 | 默认地址 |
| --- | --- |
| 后端/设备网关 | `http://<部署机IP>:8000` |
| PM | `http://<部署机IP>:8080` |
| O&M | `http://<部署机IP>:8081` |

`deploy.py init` 会在 `deploy/.env` 生成真实随机密钥，不会打印密钥，也不会覆盖已有文件。停止部署使用 `py -3.10 manager\deploy.py down`，数据卷不会删除。详细运维流程见 [部署与运维手册](部署与运维手册.md)。

正式发布包部署会把相同用途的密钥保存在 `C:\ProgramData\RobotsSystem\deploy.env`，并通过 GitHub Release 的版本化镜像升级。发布与升级流程见 [版本发布与升级](版本发布与升级.md)。

## 3. 首次初始化项目

首次打开 PM 或 O&M 页面会显示初始化页面。

1. 输入 `INITIAL_SETUP_TOKEN`。
2. 填写真实项目编码、名称、位置和地图坐标系。
3. 设置 O&M 与 PM 账号，密码至少 12 位。
4. 提交后系统创建唯一项目和账号，并自动登录 O&M 账号。

初始化只能执行一次。空页面是预期状态，不会生成演示项目或默认机器人。

## 4. O&M 端操作

### 4.1 建立地图数据

以 O&M 账号登录，点击顶部“地图维护”。

1. 新增施工点位：填写编码、名称、分类、`map` 坐标、适配设备类型、关联工序以及可选二维码属性。
2. 新增区域：填写编码、名称、区域类型、施工阶段和多边形坐标。
3. 区域多边形格式：`[[x,y],[x,y],[x,y]]`，至少三个点且面积不能为零。
4. 保存后，O&M 三维场景会自动刷新。

区域与点位必须使用外部地图网关同一套 `map` 坐标系。PM 任务必须选择已保存的施工点位。

### 4.2 注册设备

桥接程序首次注册时使用共享引导密钥：

```http
POST /api/devices/gateway/register
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

注册请求至少包含设备编码、名称、类型和能力。能力中的 `processes` 应列出该设备可执行的工序 ID。

响应中的 `device_gateway_key` 仅返回一次。必须由桥接程序安全保存；后续遥测、命令轮询、ACK 和设备资料更新均使用该设备独立密钥，不能继续使用共享引导密钥。

完整字段与示例见 [设备网关协议](DEVICE_GATEWAY_API.md)。

### 4.3 上报遥测

设备持续调用：

```http
POST /api/devices/gateway/{device_code}/telemetry
X-Device-Gateway-Key: <device_gateway_key>
```

需要提供：

- 唯一 `event_id`；重复事件会幂等处理。
- `boot_id` 和递增 `sequence`；同一启动周期内乱序事件会被拒绝。
- 当前状态、电量、`map` 坐标和健康信息。
- 可用时提供功率、累计能耗、里程、运行时长、定位漂移。
- 执行任务时提供 `mission.execution_id`、状态、进度、完成量和失败码。

没有真实上报的字段，平台不会自行估算或补造数据。

### 4.4 设备获取命令并回执

桥接程序轮询命令：

```http
GET /api/devices/gateway/{device_code}/commands
X-Device-Gateway-Key: <device_gateway_key>
```

按命令 `id` 去重并执行后，重复回传 ACK 直至成功：

```http
POST /api/devices/gateway/{device_code}/commands/{command_id}/ack
X-Device-Gateway-Key: <device_gateway_key>
```

相关命令包括 `mission_start`、`mission_pause`、`mission_resume`、`mission_cancel`、`estop`、`release`、`pause`、`resume` 和 `reset`。

ACK 只表示控制器收到了命令。任务是否真正暂停、恢复、取消、完成或失败，必须由后续遥测中的 `mission.state` 确认。

### 4.5 点云和网格地图

- 点云：O&M 先在左侧“建图模式”面板开启上传开关，桥接程序再调用 `POST /api/pointcloud/gateway/map` 上传已经融合抽样的完整 `[x,y,z]` 地图。平台只保留当前完整地图，新的 `map_id` 会替换旧地图，不再接收或合并点云快照。
- 当前地图读取接口为 `GET /api/pointcloud/map`；上传成功后 O&M 通过实时通道接收完整地图。关闭“建图模式”后，上传接口会拒绝写入，但仍可读取已经保存的当前地图。
- 运维开关接口为 `GET /api/ops/mapping` 和 `PATCH /api/ops/mapping`，请求体为 `{ "enabled": true|false }`，仅 O&M 账号可以修改。
- 地图资产：桥接程序调用 `POST /api/map/gateway/assets` 登记 `mesh_gltf`、`octomap` 或 `geojson` 外部资产。
- O&M 只加载 `map` 坐标系、浏览器可访问的 HTTPS `.gltf`/`.glb` 网格 URL。私有对象存储应使用限时且已配置 CORS 的 HTTPS URL。
- 未接入数据时页面显示等待状态，不生成虚构三维场景。

### 4.6 急停和设备控制

- “急停”会为所有注册设备写入 `estop` 命令并锁存系统状态。
- “恢复”仅 O&M 可执行，会为每台设备写入 `release` 命令。设备必须自行确认物理安全后回执。
- 单设备和批量暂停、恢复、复位、释放均先进入命令队列，不代表设备已经执行。
- 围栏和碰撞风险会触发告警和暂停命令；硬件急停、机端避障和安全继电器必须由设备侧独立实现。

## 5. PM 端操作

### 5.1 创建任务

在 PM 端新增任务时：

1. 选择工序。
2. 选择已建立的施工点位。
3. 设置计划时间、优先级、交付量、设备类型要求和前置任务。
4. 提交后任务进入数据库和 DAG，等待真实可用设备。

调度器只选择已注册、心跳有效、状态空闲/就绪、电量满足阈值、设备类型匹配且支持目标工序的设备。

### 5.2 任务状态

| 状态 | 说明 |
| --- | --- |
| `pending` | 等待前置任务或可用设备 |
| `assigned` | 已写入 `mission_start`，等待设备接受/启动 |
| `running` | 设备已上报执行中 |
| `paused` | 设备已确认暂停 |
| `reassign_pending` | 等待旧设备确认取消，尚未向新设备派发 |
| `completed` | 设备已确认完成 |
| `failed` | 设备已确认失败 |

### 5.3 暂停、恢复和改派

- 暂停：排入 `mission_pause`，在遥测确认 `paused` 前保持最后一次已确认状态。
- 恢复：针对已确认暂停的任务排入 `mission_resume`，等待遥测确认 `running`。
- 改派：先向旧设备排入 `mission_cancel`，任务进入 `reassign_pending`；收到旧设备 `cancelled` 后，才向选定设备发送 `mission_start`。

该流程用于避免两台设备同时执行同一任务。

### 5.4 报表

PM 与 O&M 可导出数据库已有的报表。报表只包含实际任务、设备事件和告警；空项目导出为空报表，不会补充示例指标。

## 6. 相机/视觉网关

相机或视觉系统先注册设备，再上报真实检测：

```http
POST /api/cameras/gateway/register
POST /api/cameras/gateway/{camera_code}/detections
X-Device-Gateway-Key: <DEVICE_GATEWAY_API_KEY>
```

未接入相机时，PM 页面显示无数据；系统不会生成 AI 检测结果。

## 7. 备份

完整部署可直接导出主机备份：

```powershell
py -3.10 manager\deploy.py backup
```

备份保存在 `deploy/backups/`。恢复必须显式确认，且会先停止应用服务：

```powershell
py -3.10 manager\deploy.py restore deploy\backups\<file>.dump --confirm RESTORE
```

O&M 页面中的备份接口同样会实际调用 `pg_dump`；未配置时会明确返回未配置，不会伪造成功。

## 8. 上线前验证

```powershell
cd backend
pytest -q
python -m compileall -q app
alembic check

cd ..\frontend
pnpm build
```

现场还应验证设备注册、心跳超时、乱序与重复遥测、任务全状态回执、急停/恢复、围栏、硬件安全回路、地图坐标一致性和备份恢复。
