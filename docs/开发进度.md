## 当前结论

系统已从演示型页面调整为数据库和外部网关驱动的调度控制平台。启动时不会生成账号、项目、设备、任务、地图、点云或摄像头检测。首次使用由项目人员录入真实项目资料；设备、地图和视觉数据由真机或外部 Gazebo 桥接程序上报。

本仓库不实现 ROS 节点、机器人固件、SLAM、导航、局部避障或 Gazebo world。它们由机器人侧或仿真侧实现，并通过 HTTP 网关协议接入。

## 关键状态机

任务状态只由真实设备遥测确认，浏览器请求和命令 ACK 不会伪造任务已执行。

1. 调度器根据真实交付量、计划窗口和设备有效单位产能规划设备类型与数量；所有完成门槛需求均覆盖后，才创建多个执行单元并分别排入 `mission_start`。
2. 每个设备只收到自己的工作配额。设备上报 `accepted`、`running`、`paused`、`completed`、`failed` 或 `cancelled` 后，后端才更新该执行单元，再聚合业务任务进度。
3. 已分配任务的暂停命令按启动命令之后送达；暂停、恢复分别等待设备上报 `paused`、`running`。
4. 单台设备失败、取消或产能变化时，平台保留已完成量并重新规划剩余资源；不会把未完成业务任务直接伪造为失败或完成。

## 当前数据原则

数据库行数和设备在线数量属于运行时状态，不在进度文档中固化。系统初始化后由项目人员录入项目资料，设备、任务、地图和视觉数据由真实网关或外部 Gazebo/CV 服务写入。`projects.mapping_enabled` 默认关闭，必须由 O&M 明确开启后才能接收完整点云地图。核验本机状态时应通过管理工具日志、O&M 页面或已鉴权 API 查询，不以本文记录的历史数量为准。

## 上线前实施事项

以下是外部实施条件，不是后端留空功能：

1. 为每台真机或 Gazebo 桥接程序实现 [设备网关协议](DEVICE_GATEWAY_API.md)。
2. 为生产环境配置强随机的 `JWT_SECRET`、`DEVICE_GATEWAY_API_KEY`、`INITIAL_SETUP_TOKEN`。
3. 在初始化页面录入真实项目、现场位置、坐标系和 PM/O&M 账号。
4. 导入真实区域、点位、点云和地图资产；网格需使用浏览器可访问的 HTTPS `.gltf` 或 `.glb` URL，并正确设置 CORS。
5. 为每台参与自动调度的设备登记真实 `work_capacities`（能力、单位产能、来源、证据、上报时间和有效期）；未登记时任务会真实显示为等待产能，不会派发。
6. 在现场联调硬件急停、围栏、速度限制、机端避障和通信中断降级。平台的命令队列不能替代机器人本体的安全回路。
